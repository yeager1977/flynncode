- A `Set` inside a Solid `createStore` is not reactive — use a plain array and `includes`.
- Solid's `<For>` reuses a row only when the item is the same reference. The sidebar session list re-fetches fresh objects, so `stableSessions` (packages/app/src/pages/layout/sidebar-sessions.ts) keeps the previous object when the row would render the same; rename state lives above the list, keyed by session id.
- Interactive terminal handoff needs the app to match the shell tool's exposed id `bash`, not `shell` (packages/flynncode/src/tool/shell/id.ts); a subagent's wait surfaces in the main session through a composer card that polls the server's live PTY list.
- Never read a `@tanstack/solid-query` `query.data` (or any `createResource` value) in a memo, JSX expression or other render computation under the route's `<Suspense>` (`pages/layout-new.tsx`). While the query is still loading the read registers a permanent Suspense reader; any later refetch, poll or stale-time expiry then blanks the whole route, the session timeline's scroller is detached and its scroll offset resets to 0 ("it keeps scrolling to the top"). Read `query.data` inside `createEffect` (user effects do not register) and mirror it into a store, or read non-data flags (`isSuccess`, `isFetching`). Pattern: `hooks/use-provider-usage.ts`. Guard: `e2e/regression/session-timeline-scroll-refresh.spec.ts` advances a fake clock and fails if the timeline is ever detached.
- Vite serves optimized dependency chunks from a cached copy with `Cache-Control: immutable`; editing a file under `node_modules/.vite/deps` for instrumentation needs a restart of your own vite server before it takes effect (and restore the file afterwards). Plain `pkill -f "<pattern>"` can match the calling shell's own command line; use a bracketed pattern like `pgrep -f '[p]laywright'`.
- Use bun for tests, from package dirs (never repo root).
- State that a Solid component reads in JSX has to live in a `createStore`: plain `Map`/`Set` fields are not tracked, so the row never re-renders (the sidebar's "Rename" did nothing). Same rule as the `Set` note above.
- The fork has no titlebar tabs and no home page (both retired in 2026-10): sessions open by navigation and the sidebar is the browser. E2E specs must reach the app through the sidebar (session rows are links `a[href="/server/<base64url(serverUrl)>/session/<id>"]` inside `navigation "Projects and sessions"`) or a direct URL - the old `home-session-row`, `home-add-project-row` and `[data-slot="titlebar-tabs"]` selectors are gone.
- The e2e mock server (packages/app/e2e/utils/mock-server.ts) answers the routes the app polls: `/session/:id/shells`, `/session/:id/schedules`, `/preview/servers`, `/pty/shells` as lists and the v2 catalog (`/api/provider`, `/api/model`, `/api/model/default`) as `{ data }`. An unstubbed route answers `{}`, and a list reader that gets an object throws inside the app's error boundary.
- The mock's default SSE body is finite, so the app reconnects (~250 ms) and reloads the routed session on every event (context/server-session.ts `distrustLoaded`). Specs that need a steady UI hold one stream open with `e2e/utils/sse-transport.ts` `installSseTransport`.
- Timeline scroll compensation: a row that is hidden behind the sticky session title still shifts the rows in view when its measured size replaces the 60px estimate, so the predicate in `pages/session/timeline/bottom-lock.ts` (`isHiddenAboveViewport`) compares against `offset + scrollMargin`, not the first visible row index.
- To recover lost feature wiring, extract a known-good deb's app.asar with `bunx @electron/asar` (npx fails: "asar: not found") and grep for feature strings before re-deriving by hand.
