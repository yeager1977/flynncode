Before launching parallel agents on this box, check for runaway processes and free memory first. On 2026-10-20 an orphaned `bun test` in packages/flynncode ran 6h+ at 100% CPU holding 3.1 GB RSS (no child processes, dead stdout pipe), and two pytest runs in ~/GitHub/rob-etl held 2 GB and 2 cores for 5.5h/1.6h. The box was at 46/59 Gi RAM with only ~13 Gi available and the 4 Gi swap fully consumed, which is the known way the desktop app crashes (see crash-investigation). Killing the three runaways restored ~18 Gi available. The agent launcher itself was healthy (a probe subagent returned in seconds) — the problem was resources, not the launcher. Also note: concurrent agent sessions share one working tree, so parallel commits/pushes collide (a push was rejected for 179MB .debdebug blobs and a peer's rebase rewrote another session's commit hash) — have parallel agents do code work and leave commits serialized by the owner.
