The dev session DB grows without bound because the v2 event log re-stores full payloads: `~/.local/share/opencode/opencode-dev.db` reached 15.3 GB with 1.26M events — 911,592 `message.part.updated` (each holding the whole part JSON, ~10 KB average, max 6 MB), 272k `message.updated`, 77k `session.updated`. Freelist is 0, so it is live data, not bloat: VACUUM reclaims nothing; the fix is to cap/dedupe part-update payloads at write time (or store a diff). Symptom: DB reads get slow (a grouped scan took 1.1s; heavier aggregates ran >3min), so the sidebar/session list and event replay get sluggish as history grows. Every agent turn adds more, so parallel agent runs multiply the growth. Probe read-only with bun:sqlite; do not rewrite or vacuum the owner's DB without asking.
