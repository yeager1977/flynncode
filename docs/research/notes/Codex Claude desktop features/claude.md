# Claude desktop features

Research date: 30 September 2026. Scope is Anthropic’s Claude Desktop app (macOS, Windows, Linux beta), including Cowork, computer use, and the embedded Claude Code tab. Claude Code CLI is noted only where Desktop embeds or hands off to it. Pages were fetched that day. “Updated today / this week / over 2 weeks ago” are the Help Center relative stamps on those fetches, not independent publication dates.

## Distinctive desktop UX

### Takeaway

As of 30 September 2026, Claude Desktop is the local shell for one signed-in Claude account: Chat, Cowork (being merged into ordinary chat on Pro and Max), and a Code tab that embeds Claude Code. Distinctive desktop traits are dock/quick access, local folders and desktop extensions, a built-in browser, computer use, and Code-tab panes (preview, diff, terminal, pop-out windows). Model inference and, by default, Cowork agent loops still run on Anthropic infrastructure.

Downloads also list Windows arm64, ChromeOS via the Play Store listing, and a separate Claude Science beta installer. Apps exist on Free, Pro, Max, Team, and Enterprise; some features are paid-only. Linux FAQ: Chat on all plans including Free; Claude Code and Claude Cowork on Pro, Max, Team, and Enterprise. Install article prose: Cowork is for paid plans on macOS, Windows, and Linux beta. Linux does not self-update; updates come from apt. — [Install Claude Desktop](https://support.claude.com/en/articles/10065433-install-claude-desktop) (Help Center: updated this week); [Download Claude](https://claude.com/download) (fetched 30 September 2026).

- App shape. Download page: the desktop app is always reachable from the dock and includes quick entry; it is “all of Claude, in one app,” working with files and apps. Claude Code docs: three tabs — Chat, Cowork (Dispatch and longer agentic work), and Code. The Code tab is the desktop reference for software sessions. — [Download Claude](https://claude.com/download); [Desktop application](https://code.claude.com/docs/en/desktop) (fetched 30 September 2026).

- Quick entry and window capture. On macOS, quick entry is for all plans: double-tap Option (or Option+Space / custom) opens a composer from any app while Desktop runs in the background; drag-to-screenshot; click an application window to attach it; five most recent chats via “New chat.” macOS 12+ for quick entry; macOS 14+ for Caps Lock dictation. Requires Screen Recording, Accessibility, and (for dictation) Speech Recognition. The dedicated article says quick entry is not on Windows. Install and download FAQ say the global hotkey also works on Linux X11, and on native Wayland only via the desktop GlobalShortcuts portal. — [Use quick entry with Claude Desktop on Mac](https://support.claude.com/en/articles/12626668-use-quick-entry-with-claude-desktop-on-mac); [Install Claude Desktop](https://support.claude.com/en/articles/10065433-install-claude-desktop); [Download Claude](https://claude.com/download).

- Deep links. `claude://` opens Desktop on macOS, Windows, and Linux, launching the app if needed. Supported: new chat (`claude://claude.ai/new?q=`), existing chat or project by UUID, new Code session (`claude://code/new` with optional `q`/`prompt` and one `folder`; `file` accepted but not currently supported), new Cowork session (`claude://cowork/new` with repeatable `folder` and `file`). Prompt `q` is truncated to about 14,000 characters. Any folder from a link is treated as untrusted and must be confirmed, even if previously trusted. — [Open Claude Desktop with a link](https://support.claude.com/en/articles/14729294-open-claude-desktop-with-a-link).

- Projects. Conversations, projects, memory, and preferences sync across devices when signed in; Cowork local sessions stay on-device. Cowork projects exist on desktop, web, and mobile. A project can start a chat or a Cowork session and supplies project knowledge. Projects tied to a local folder support Cowork sessions on desktop only, and Cowork will not change a project’s contents. In the Code tab, sidebar Projects start and track multiple cloud code sessions from one conversation. — [Download Claude](https://claude.com/download); [Use Claude Cowork on web, desktop, and mobile](https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile); [Desktop application](https://code.claude.com/docs/en/desktop).

- Artifacts and in-place preview. 16 September 2026 release notes: designs, decks, and docs can be requested in any conversation, including Claude Code and the Artifacts tab, and edited on canvas or with Claude. Artifacts, including Claude Design, Claude Slides, and Claude Docs, are on every plan including Free; on Enterprise those three are beta and off until an owner enables them. Cowork surface table: preview of files Claude creates is on desktop, web, and mobile. Live artifacts created before 19 August 2026 are desktop-only. Artifacts created on or after 19 August 2026 are on desktop and web (the table does not mark them available on mobile). Cowork can highlight Markdown and “Edit with Claude” in place. 12 June 2026: drafts in chat or Cowork open beside the chat for in-place edits. — [Release notes](https://support.claude.com/en/articles/12138966-release-notes); [Use Claude Cowork on web, desktop, and mobile](https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile); [Get started with Claude Cowork](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork) (Help Center: updated today).

- Cowork, then “one Claude.” 12 January 2026: Cowork research preview on Claude Desktop, macOS only, Max plans; described then as running locally in an isolated VM with local files and MCP. 16 January 2026: expanded to Pro, still macOS only. 9 April 2026: generally available on macOS and Windows, plus Analytics API, usage analytics, and OpenTelemetry. 25 February 2026: scheduled tasks and a Desktop Customize section grouping skills, plugins, and connectors. 7 July 2026: Cowork on web and mobile, rolling out from Max; sessions remote (beta); chat and Cowork share one home. 16 September 2026 blog and release notes: Cowork and chat merge so Claude chooses whether a message is a quick answer or a task. Rolling out gradually to Pro and Max on web, desktop, and mobile over the following weeks; Team and Free to follow; Enterprise admins get at least 30 days’ notice. Accounts that still show Chat and Cowork have not moved. Once moved, you cannot switch back. The Code tab and model picker stay. New-experience limitations: no “Add from GitHub”; no branching from an earlier point; incognito chats open in the previous experience and cannot create files or run code; search does not include older Cowork tasks; Dispatch is not available to new users (existing Dispatch users can keep it for now). — [Release notes](https://support.claude.com/en/articles/12138966-release-notes); [Claude Cowork and chat are now one Claude](https://claude.com/blog/cowork-is-now-claude) (dated 16 September 2026); [Claude Cowork and chat are one Claude](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude).

- Scheduled tasks. Paid plans (Pro, Max, Team, Enterprise), in Cowork and in the new Pro/Max experience. Each run is its own Cowork session. Cadences documented for manual setup: hourly, daily, weekly, weekdays, or manually; optional model; optional folder. Create via `/schedule`, sidebar “Scheduled,” or by describing the cadence. As of the 30 September 2026 fetch, scheduled tasks run remotely even if the computer is asleep or Desktop is closed, and “can’t be tied to a folder on your computer.” The same article also says a task that requires local files or apps “will only run locally.” — [Schedule recurring tasks in Claude Cowork](https://support.claude.com/en/articles/13854387-schedule-recurring-tasks-in-claude-cowork); [Release notes](https://support.claude.com/en/articles/12138966-release-notes) (25 February 2026).

- Connectors versus desktop extensions. Web connectors (examples named: Google Drive, Slack, Gmail, Microsoft 365) work on web, desktop, and mobile. Desktop also has desktop extensions: locally installed MCP packages (`.mcpb`) for local files, browsers, and native apps, installed from Settings > Extensions or a directory of Anthropic-reviewed tools. Claude Desktop bundles Node.js, so Node install is not required; Python and binary servers are also supported. Sensitive config is encrypted in OS secure storage (Keychain, Credential Manager, distro keychain). Official-directory extensions update automatically; private `.mcpb` files do not. Team/Enterprise owners can enable/disable public extensions, upload custom ones, and use an allowlist. Device policy keys `isDesktopExtensionEnabled` and `isDesktopExtensionDirectoryEnabled` override in-app lists. `isLocalDevMcpEnabled=false` disables plugin-bundled and locally configured MCP servers. Local connectors and plugins that include local MCP servers work through the desktop app only. — [Download Claude](https://claude.com/download); [Getting Started with Local MCP Servers on Claude Desktop](https://support.claude.com/en/articles/10949351-getting-started-with-local-mcp-servers-on-claude-desktop); [Claude Cowork architecture overview](https://support.claude.com/en/articles/14479288-claude-cowork-architecture-overview); [Use Claude Cowork on web, desktop, and mobile](https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile).

- Memory. Download FAQ: memory syncs across phone, desktop, and web. 2 March 2026: chat-history memory for all users including free, plus import/export. 10 July 2026: memory is individual categorized entries, not a daily summary. 25 August 2026: memory works across chat and Cowork in the cloud; topics editable in Settings > Memory; health/beliefs excluded unless “Include sensitive topics in memory” is on; on by default for Free/Pro/Max, off by default for Team/Enterprise. Cloud Cowork shares chat memory; a single task can start with Memory off in the “+” menu, and that choice is fixed for the task. Computer-use article: some data is never saved (government ID numbers, criminal history, financial account numbers, immigration status). Memory from Cowork tasks that ran only on the computer stays with those tasks. 9 July 2026: monthly recap (Settings > Reflect) is beta on Free/Pro/Max on web and Claude Desktop and requires memory on. — [Download Claude](https://claude.com/download); [Release notes](https://support.claude.com/en/articles/12138966-release-notes); [Get started with Claude Cowork](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork); [Let Claude use your computer in Cowork](https://support.claude.com/en/articles/14128542-let-claude-use-your-computer-in-cowork); [Claude Cowork and chat are one Claude](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude).

- Voice. Two different features. Voice mode is a beta spoken conversation (hear Claude’s voice) on all plans, on Claude Mobile, Claude Desktop, and the web, “built to work best from your phone.” Desktop/web: sound-wave control in the chat window; hands-free or push-to-talk; voice choice under Settings > General > Voice settings; starts on the last text-chat model family and can switch models, but Claude Fable is not available in voice mode; usage counts toward plan limits. Separate from that, macOS quick entry has Caps Lock dictation that transcribes speech to text and sends the text; it is off by default because it takes over Caps Lock. Linux install limitations: dictation is not available in that release. — [Use voice mode](https://support.claude.com/en/articles/11101966-use-voice-mode); [Use quick entry with Claude Desktop on Mac](https://support.claude.com/en/articles/12626668-use-quick-entry-with-claude-desktop-on-mac); [Install Claude Desktop](https://support.claude.com/en/articles/10065433-install-claude-desktop); [Download Claude](https://claude.com/download).

- Computer use. Research preview / beta on Pro and Max only, in Cowork and Claude Code inside Claude Desktop, macOS and Windows. Not on Team or Enterprise. Not on Linux. Off until Settings > General (Desktop app) > Enable computer use. Tool order in Cowork: connectors, then browser, then screen. Claude takes screenshots of permitted apps. Per-app permission prompts; some apps blocked by default (investment, trading, cryptocurrency named); user app blocklist. No sandbox between Claude and the desktop. On macOS 15+, default is background windows so the user keeps pointer and keyboard; first full-screen takeover in a session asks permission; Settings can force “Full control.” Computer must be awake and Desktop open. Code docs add: macOS also needs Accessibility and Screen Recording; iOS Simulator pane does not require computer use. Dispatch-spawned Code sessions re-prompt app approvals after 30 minutes. — [Let Claude use your computer in Cowork](https://support.claude.com/en/articles/14128542-let-claude-use-your-computer-in-cowork) (Help Center: updated over 2 weeks ago); [Release notes](https://support.claude.com/en/articles/12138966-release-notes) (23 March 2026); [Desktop application](https://code.claude.com/docs/en/desktop); [Download Claude](https://claude.com/download).

- Built-in browser versus Claude in Chrome. A browser built into Desktop is rolling out gradually “this week” (relative to the 30 September 2026 fetch) for Cowork on macOS, Windows, and Linux beta, on Pro, Max, Team, and Enterprise where an owner enabled it. It opens in a side panel; Claude clicks, types, and fills forms. Cookie import from Chrome, Edge, and Firefox on macOS, and Firefox on Windows and Linux; not from Safari. Banking, email, and SSO stay unchecked by default. If Claude in Chrome is already used, it remains the Cowork default; otherwise the built-in browser becomes default. Preferred browser is Settings > Cowork. Sign-ins inside the built-in browser persist for later Cowork sessions on that computer. Download FAQ: Claude in Chrome is a connector; from Desktop, Claude can navigate, click, and fill forms in the user’s browser. — [Use the built-in browser in Claude Cowork](https://support.claude.com/en/articles/16607400-use-the-built-in-browser-in-claude-cowork); [Download Claude](https://claude.com/download).

- Code sessions inside Desktop. A Code session has its own history and project folder. Environment choices: Local, Cloud, SSH, and on Windows a WSL distribution. Permission modes: Manual (default), Accept edits, Plan, Auto (Opus 4.6+ / Sonnet 4.6+ / a Fable model; no separate Settings toggle), Bypass permissions (Pro/Max Settings toggle “Allow bypass permissions mode”; Team/Enterprise governed by org policy; not in cloud sessions). Earlier labels were Ask permissions, Auto accept edits, and Plan mode. `dontAsk` is CLI-only. Sidebar parallel sessions; Git worktree isolation under `<project-root>/.claude/worktrees/`; Cmd/Ctrl-click opens a second session pane. Panes: chat, diff, browser, terminal, file, plan, tasks, subagent, plus iOS Simulator on macOS. Drag to rearrange. Pop a pane (diff or terminal named) into its own window and dock it back; requires Claude Desktop v1.2581.0 or later. Preview: Claude can start a dev server and open it in the Browser pane, auto-verify with screenshots, DOM, clicks, and forms; also opens project HTML, PDF, images, and videos. Browser is tabbed (Cmd/Ctrl+Shift+B). Integrated terminal is local sessions only (Ctrl+`). Diff commenting and “Review code”; CI status via GitHub CLI `gh`, with auto-fix and squash auto-merge toggles. `/desktop` in the CLI (macOS and x64 Windows, Claude subscription sign-in, not API key or Bedrock/Agent Platform/Foundry) saves the session and opens it in Desktop. `/resume` in a local Desktop session lists CLI sessions on this computer. Desktop and CLI can run at once; they share CLAUDE.md and settings files but keep separate session lists. Not in Desktop: inline autocomplete; agent teams (CLI only; dynamic workflows do run in Desktop); some terminal-dialog commands (`/permissions` replies that it isn’t available; `/config` opens Settings). Admins can disable local Code sessions with `disableDesktopLocalSessions`. — [Desktop application](https://code.claude.com/docs/en/desktop); [Download Claude](https://claude.com/download).

- Dispatch and phone handoff. 17 March 2026: persistent agent thread on Desktop or iOS/Android for Pro/Max, research preview, Max first. 23 March 2026: computer use makes Dispatch able to use the computer while the user is away. Code docs: Dispatch lives in the Cowork tab; it can spawn a Code session (sidebar badge “Dispatch”); Pro/Max only, not Team or Enterprise. Download page: pair mobile and desktop so a phone task can start in Cowork; Remote Control on mobile sends tasks to the Claude Code CLI for the local dev environment. The 16 September 2026 help article says Dispatch is not available to new users. — [Release notes](https://support.claude.com/en/articles/12138966-release-notes); [Desktop application](https://code.claude.com/docs/en/desktop); [Download Claude](https://claude.com/download); [Claude Cowork and chat are one Claude](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude).

- Permissions (Cowork). Three modes in the message box: Manual (asks; connector “Always allow” is approved, “Needs approval” asks, “Blocked” denied), Auto (read-only connector tools approved; write/delete decided by Claude after a safety check; blocked still denied; uses more of the usage limit), Skip (approves everything not blocked; no automatic safety check). Team/Enterprise admins can hide automatic approval and can require per-task approval for write-capable connector tools. — [Get started with Claude Cowork](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork); [Claude Cowork and chat are one Claude](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude).

EDR cannot inspect the local Cowork VM or cloud sessions. — [Download Claude](https://claude.com/download); [Claude Cowork architecture overview](https://support.claude.com/en/articles/14479288-claude-cowork-architecture-overview); [Enterprise configuration](https://support.claude.com/en/articles/12622667-enterprise-configuration-for-claude-desktop) (linked, not fully fetched).

### Inferences

- The distinctive desktop interaction, as Anthropic documents it, is not a separate model: it is local reach (folders, extensions, browser, screen, Code panes) wrapped around the same account as web and mobile.
- “Preview” in official docs means at least three things: Code-tab Browser pane for running apps and files, Cowork file preview of generated outputs, and voice-picker audio preview. It is not one feature.
- “Multi-window” is not a named product mode. The documented equivalents are Code-tab pane pop-out (v1.2581.0+), a two-session split, and quick entry attaching another app’s window.

### Gaps

- No official page found that names a general multi-window chat (several independent Chat windows). Absence is from these fetches, not a proof it cannot exist in the UI.
- The projects help article (`https://support.claude.com/en/articles/9517075-what-are-projects`) and the full artifacts article were not fetched; project and artifact facts above are only what Desktop, Cowork, download, and release-note pages state.
- Install-article plan table cells for Free versus Claude Code did not survive HTML-to-text conversion, so Free access to the Code tab on macOS/Windows is not confirmed here. Linux FAQ is explicit that Code and Cowork are paid.
- Enterprise configuration article body was not fetched; only keys and behaviors cited by the architecture and Code docs pages are included.
- No independent review corpus was collected. Strengths and weaknesses below are Anthropic’s positioning plus documented limits, not user-sentiment scores.

## Which features require Anthropic cloud versus local execution?

### Takeaway

Chat, memory, web connectors, and model inference are account/cloud features that sync. Desktop-only local execution is file/folder access, desktop extensions, the built-in browser, computer use, local Code sessions, and (until 6 October 2026 for Pro and Max) an explicit “Only on your computer” Cowork option. As of 30 September 2026, new Cowork work is documented as cloud-by-default, with the desktop app as a broker when a cloud session needs the machine.

### Cited Findings

- Cowork cloud default, dated. Get-started article (Help Center stamp: updated today, 30 September 2026): Cowork runs tasks in the cloud (in beta) on Anthropic servers in an isolated environment; sessions and files save to the Claude account; work continues if the laptop closes; internet is required throughout. Local file access, browser use, and computer use still need Claude Desktop for macOS or Windows open and connected. Architecture page (stamp: updated over 2 weeks ago): cloud by default (agent loop and code execution on Anthropic servers); local execution “remains available for existing desktop deployments.” Cloud sandbox: no private/internal/link-local/metadata access by default; egress via a mandatory proxy; connector tokens never enter the sandbox; device access only through Desktop, only for connected folders, only while the app is online. Files opened through Desktop are processed on Anthropic servers, not kept only on device. Team/Enterprise conversation data is not used to train Claude under the same commercial commitments as other Team/Enterprise data. — [Get started with Claude Cowork](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork); [Claude Cowork architecture overview](https://support.claude.com/en/articles/14479288-claude-cowork-architecture-overview); [Use Claude Cowork on web, desktop, and mobile](https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile).

- Upcoming local-option removal. Pro and Max: on 6 October 2026, new Cowork tasks run in the cloud and “Only on your computer” in Settings > General is removed. Tasks already started on the computer stay there, with a transcript download. Folders stay on the computer; Claude fetches a copy of a needed file; copies are deleted when the session is deleted. Scheduled tasks move to the cloud, including ones that use local files, but those still need Desktop open. The surfaces article says if you want tasks to stay on one machine, use Claude Code in the desktop app; projects and scheduled tasks do not carry over to Claude Code. — [Get started with Claude Cowork](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork); [Use Claude Cowork on web, desktop, and mobile](https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile).

- Conflicting local-VM descriptions still live. 12 January 2026 release note: Cowork “runs locally on your computer in an isolated VM.” Install article (updated this week): “Cowork runs code in an isolated virtual machine on your computer. File reads and writes are limited to folders you connect.” Linux Cowork setup still requires KVM, membership in the `kvm` group, QEMU packages, about 25 GB free for the workspace image, at least 8 GB RAM, and 4 GB while running. Architecture page: local sessions run the agent loop natively on device (conversation, connected-folder IO, web fetches, local plugin MCP) and run shell/code in a Linux VM (Apple Virtualization.framework on macOS, Hyper-V on Windows) with its own egress filtering. If the VM cannot start, file and web tools continue and shell/code report “workspace unavailable.” Download FAQ: “In Claude Cowork, local sessions stay on-device.” — [Release notes](https://support.claude.com/en/articles/12138966-release-notes); [Install Claude Desktop](https://support.claude.com/en/articles/10065433-install-claude-desktop); [Claude Cowork architecture overview](https://support.claude.com/en/articles/14479288-claude-cowork-architecture-overview); [Download Claude](https://claude.com/download).

- What still needs the open desktop app even for a cloud session: local file access (connected folders only; a cloud session can read/write those folders only while Desktop is open and, per the surface table note, only if the session was started on desktop); local connectors and local MCP plugins; built-in browser (Desktop must be open and online; if preferred browser is Claude in Chrome, web/mobile tasks use the extension and the session must be connected to a desktop, but the app need not be open); computer use (awake machine, Desktop open). If Desktop is closed, a cloud session keeps running but cannot reach local files. Scheduled tasks that are not tied to a local folder run with no device online. — [Use Claude Cowork on web, desktop, and mobile](https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile); [Use the built-in browser in Claude Cowork](https://support.claude.com/en/articles/16607400-use-the-built-in-browser-in-claude-cowork); [Schedule recurring tasks in Claude Cowork](https://support.claude.com/en/articles/13854387-schedule-recurring-tasks-in-claude-cowork); [Let Claude use your computer in Cowork](https://support.claude.com/en/articles/14128542-let-claude-use-your-computer-in-cowork).

- Code tab split. Local: agent and tools on the machine; terminal only in local sessions; file pane in local and SSH; `@mention` files not available in cloud or WSL. Cloud: Anthropic-managed infrastructure, continues if the app closes, usage against plan limits with no separate compute charge, multiple repositories, environments with network-access levels. SSH: remote machine the user manages. “Continue in Claude Code on the Web” pushes the branch and creates a new cloud session; requires a clean working tree; not for SSH. Admins can gray out Local. macOS Dock/Finder launch does not inherit the full shell environment (PATH and a fixed set of Claude Code variables from the shell profile only). — [Desktop application](https://code.claude.com/docs/en/desktop).

- Sync versus stay-local. Signed-in conversations, projects, memory, and preferences sync across desktop, web, and mobile. Cowork local sessions stay on-device. Web connectors work on every surface. Desktop extensions are local installs. Voice mode and quick-entry dictation send content to Claude as part of the conversation (dictation article: transcribed text is sent like any other text; it does not say audio is retained as a recording). — [Download Claude](https://claude.com/download); [Use quick entry with Claude Desktop on Mac](https://support.claude.com/en/articles/12626668-use-quick-entry-with-claude-desktop-on-mac).

- Network caveat. Cowork respects network egress permissions, but those permissions do not apply to web fetch, web search, or MCPs including Claude in Chrome. Web fetch runs server-side and is limited to search results and URLs the user shared. — [Get started with Claude Cowork](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork).

### Inferences

- “Local” in September 2026 docs does not mean the model runs on device. It means either an older on-device Cowork VM/agent loop, or a cloud agent reaching the device through Desktop.
- The 6 October 2026 Pro/Max change, already announced on 30 September, is the cleanest official statement of direction: new Cowork tasks in the cloud; on-device continuity is Claude Code in the desktop app, not Cowork.
- Linux Cowork, as the install article still specifies KVM/QEMU, is the clearest remaining local-VM path. That page was updated the same week as the cloud-default articles, so both descriptions are current and unresolved.

### Gaps

- Whether Team and Enterprise “Only on your computer” survives 6 October 2026 is not stated. The removal notice is explicitly Pro and Max. Architecture says local execution remains for existing desktop deployments and that Team/Enterprise keep separate chat and Cowork until the merge, with 30 days’ notice.
- No fetched page states that model weights or inference run on the user’s machine.
- The scheduled-tasks article contradicts itself on whether a local-folder schedule can exist (“can’t be tied to a folder” versus “only run locally” if local files or apps are required). Both sentences are on the same page fetched 30 September 2026.
- Trust Center PDF linked from the architecture article (`https://trust.anthropic.com/resources`) was not fetched.

## What is the best part of the Claude desktop experience, and what is weak?

### Takeaway

Anthropic’s own positioning treats the best part as one signed-in app that can answer, hand off multi-step work, and code, while reaching local files and apps and continuing in the cloud when the laptop closes. Official docs do not rank features. The documented weak points are a cloud/local transition with conflicting pages, computer use’s beta limits and lack of a sandbox, Linux gaps, and agentic usage cost.

### Cited Findings

- What Anthropic highlights as the desktop difference. Versus the browser: dock access, quick entry from anywhere in the system, and desktop extensions for local tools and files. Versus a terminal: Code tab for parallel sessions, side-by-side panes, and visual review; CLI for scripting. Cowork pitch: describe an outcome, step away, come back to finished files; sub-agents; scheduled tasks; projects with their own files, instructions, and memory. 16 September 2026 blog: the frustrating part users reported was deciding whether a task belonged in chat, Cowork, or Design, and work not carrying across those places; the merge is the response. Download page: “Think, hand off tasks, and code, all in one place.” — [Download Claude](https://claude.com/download); [Desktop application](https://code.claude.com/docs/en/desktop); [Get started with Claude Cowork](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork); [Claude Cowork and chat are now one Claude](https://claude.com/blog/cowork-is-now-claude).

- Documented product limits Anthropic states as current. ### Inferences

- The strongest officially documented desktop trait is continuity: one account, quick entry on Mac, local reach when the app is open, and cloud continuation when it is not.
