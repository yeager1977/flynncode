# Codex desktop app (ChatGPT desktop app, Codex mode)

Researched 2026-09-30 from official docs and changelog entries through 2026-09-30. The product launched 2026-02-02 as the Codex app for macOS. As of the docs fetched this date, `https://developers.openai.com/codex/app` is titled **ChatGPT desktop app**, and Codex is a mode inside it. On 2026-07-09, changelog entry “Codex joins the ChatGPT desktop app 26.707” said existing Codex app users keep projects, settings, and workflows, can make Codex the default view, and on macOS can keep the Codex app icon.

Docs pages are surface-switched (`app` / `web` / `cli` / `ide`). Findings below are the **app** surface unless noted. Markdown mirrors live at the same path plus `.md`. The docs index also points at `https://learn.chatgpt.com/llms.txt`.

## What are the distinctive desktop UX traits?

### Takeaway

The coding desktop surface is a project sidebar plus parallel chats, with Local / Worktree / Cloud placement, an in-app Git review pane, and a separate Code Review plugin. Later 2026 additions — built-in browser with page annotations, computer use, voice, skills/plugins, scheduled tasks, local memories, and subagent threads — sit in the same app and are usable from Codex, but several are ChatGPT-desktop features rather than Codex-only.

### Cited Findings

#### Product frame and navigation

- 2026-02-02: OpenAI launched the Codex app for macOS as a desktop interface for parallel agent threads, with a project sidebar, thread list, and review pane. Listed launch traits: multitask across projects, built-in worktrees, voice dictation, built-in Git tooling, skills, automations. The app picks up session history and configuration from the Codex CLI and IDE extension, and uses the same open-source system sandbox as the CLI. — [Introducing the Codex app](https://openai.com/index/introducing-the-codex-app/); [Changelog, 2026-02-02](https://developers.openai.com/codex/changelog)
- Blog update on that same post: “March 4, 2026 update: The Codex app is now available on Windows.” Changelog 2026-02-12 only says Windows alpha testing was starting. A June 2026 third-party review dates Windows shipping to 2026-05-29; that date matches the changelog’s Windows **computer use and remote control** release (26.527), not the blog’s Windows availability note. — [Introducing the Codex app](https://openai.com/index/introducing-the-codex-app/); [Changelog, 2026-02-12 and 2026-05-29](https://developers.openai.com/codex/changelog); contradicted on the May 29 “Windows shipped” reading by [vibecoding.app review, updated 2026-06-17](https://vibecoding.app/blog/openai-codex-app-review)
- 2026-07-09, app 26.707: Codex became part of the ChatGPT desktop app on macOS and Windows. New in that drop: edit Markdown and code in the app with inline annotations; PR Chat for GitHub pull requests (inline feedback, inspect patches, edit/accept/reject); custom domains on Sites; plugin management moved into Settings; clearer Full access warnings. — [Changelog, 2026-07-09](https://developers.openai.com/codex/changelog)
- Current app quickstart (fetched 2026-09-30): install, sign in with a ChatGPT account, then start a chat, create a project, or open a folder. Composer choice is **ChatGPT or Codex**. In ChatGPT, a toggle selects Chat or Work. In Codex, start with New chat; Quick chat is a separate icon. — [ChatGPT desktop app](https://developers.openai.com/codex/app)
- Quick chat opens an ordinary ChatGPT chat and does **not** appear in the Codex sidebar. Shortcuts: Cmd+Option+N (macOS), Ctrl+Alt+N (Windows/Linux). From New chat you can open an existing ChatGPT chat and add it to a Codex chat. — [Projects and chats](https://developers.openai.com/codex/projects)
- Sidebar organization in the app: pin projects and chats, rename chats, search projects, search chats (no default shortcut; assign one under Settings > Keyboard Shortcuts), archive a chat or archive a project’s chats together, restore from Settings > Archived chats. Pinning does not add context. — [Projects and chats](https://developers.openai.com/codex/projects)
- Features page Add menu (fetched 2026-09-30) shows Files and folders, Attach Google Chrome, Goal, and Plan mode, plus document/PDF/spreadsheet/presentation plugins. — [Features](https://developers.openai.com/codex/features)
- 2026-09-11, app 26.908: floating Pets controls can send a quick chat (Enter to send, `@` for context, `$` for a skill) and a bell to follow threads. Show-pet shortcut Option+Space (macOS) or Windows+Alt+P. — [Changelog, 2026-09-11](https://developers.openai.com/codex/changelog); [Notifications](https://developers.openai.com/codex/notifications)

#### Threads / projects

- App Projects view mixes ChatGPT projects and **local projects** bound to folders. A local project can attach multiple folders; every attached folder is readable and writable. **Make primary** sets the default working directory. New chats, Git operations, and automatic discovery of `AGENTS.md`, skills, and `config.toml` use the primary folder. Secondary folders are searchable/editable but are not auto-scanned for those project files. Remote projects support one folder. — [Projects and chats](https://developers.openai.com/codex/projects)
- Multi-folder local projects shipped 2026-07-23 (app 26.715). — [Changelog, 2026-07-23](https://developers.openai.com/codex/changelog)
- When sync is on, “Local computer access with Work Cloud” lets the cloud coordinate **new** tasks that can continue across desktop, mobile, and web. Existing tasks, including those in projects, stay local-only or cloud without local-file access. If the computer is unavailable when a new turn starts, an eligible task can continue in a cloud container that cannot access the computer’s files or tools. Work cannot switch local↔cloud mid-turn. Syncing a conversation does not upload the whole local folder. Work conversation history is separate from Codex history. — [Projects and chats](https://developers.openai.com/codex/projects)
- CLI does not expose the ChatGPT Projects view; it treats the start directory as the project. — [Projects and chats](https://developers.openai.com/codex/projects)

#### Worktrees

- In the new-chat composer, **Worktree** is a placement next to Local. Choose a starting branch (main/master, a feature branch, or the current branch including unstaged changes). Codex creates a Git worktree, detached HEAD by default, under `$CODEX_HOME/worktrees`. Settings > Worktrees can change **Worktree root**. — [Worktrees](https://developers.openai.com/codex/environments/git-worktrees); [Codex environments](https://developers.openai.com/codex/environments/modes)
- **Handoff** moves a chat and its code between Local and Worktree. Git allows a branch to be checked out in only one worktree. Each chat keeps the same associated worktree; handing back returns to that worktree. `.gitignore` files do not move unless listed in `.worktreeinclude` (or the automatic copy of ignored `AGENTS.override.md`). — [Worktrees](https://developers.openai.com/codex/environments/git-worktrees)
- Header actions on a worktree chat: **Create branch here**, **Open** (IDE), integrated terminal. **Hand off** is in the chat header. — [Worktrees](https://developers.openai.com/codex/environments/git-worktrees)
- Codex-managed worktrees are per-chat and disposable. Permanent worktrees are created from the project three-dot menu and are their own project; they are not auto-deleted and can host multiple chats. Default retention is the 15 most recent managed worktrees; configurable, or automatic deletion can be turned off. Not auto-deleted if a pinned chat is tied to it, the chat is in progress, or it is permanent. Archived chats and over-limit older worktrees are deleted after a snapshot; reopening offers restore. — [Worktrees](https://developers.openai.com/codex/environments/git-worktrees)
- 2026-02-03 changelog: renamed **Sync** to **Handoff**. — [Changelog, 2026-02-03](https://developers.openai.com/codex/changelog)
- Non-Git projects cannot use worktrees. Scheduled tasks in non-Git projects run in the project directory. — [Worktrees](https://developers.openai.com/codex/environments/git-worktrees); [Scheduled tasks](https://developers.openai.com/codex/automations)

#### Diffs and review

- Two different review UIs. (1) **Review pane** for local Git changes: scopes Unstaged (default), Staged, Commit, Branch, Last turn. Includes Codex edits and any other uncommitted changes. Inline comments via hover **+**, then a follow-up message such as “Address the inline comments.” Stage/unstage/revert at diff, file, or hunk. Clicking a filename opens the chosen editor; filename background expands the diff; Command-click a line opens that line. Multi-folder projects get a repository selector; Last turn can show **All repos**. `/review` offers “Review against a base branch” or “Review uncommitted changes” and does not change the working tree. Findings are inline comments. Settings > General > Code review can run reviews in the current chat or **Detached**. — [Code review](https://developers.openai.com/codex/code-review)
- (2) **Code Review plugin**, pinnable in the sidebar: PR description, changed files, comments, checks. GitHub code review is generally available; GitLab merge-request support is in preview. Personal inbox filters: Assigned to me, Assigned to my team, Authored by me. Mark as viewed is per displayed revision. Stack section opens related PRs. **Review with Codex** starts a new chat; **Review instructions** (also Settings > Code Review) apply across repos. Optional Comic book / Visualization / PDF instruction add-ons. Chat review does not post, approve, or merge until the user submits. **Submit review** sends Comment, Approve, or Request changes. Posting in Summary or Changes sends immediately, without waiting for Submit review. **Fix** on failing checks attaches them to the chat but does not send until the user sends. — [Code review](https://developers.openai.com/codex/code-review)
- 2026-07-30, app 26.727: review pane can show all repositories in a multi-folder project and lines changed in each. — [Changelog, 2026-07-30](https://developers.openai.com/codex/changelog)
- 2026-02-06, app 26.206: removed the overall diff-size cap in the review pane. — [Changelog, 2026-02-06](https://developers.openai.com/codex/changelog)

#### Computer use, app preview, appshots

- Computer Use is a plugin (MCP server + skill toggles) for ChatGPT Work and Codex on macOS and Windows, region-limited. It sees and operates GUIs. macOS needs Screen Recording and Accessibility for “Codex Computer Use.” Windows runs on the active desktop and cannot operate in the background of the same session; it takes pointer and keyboard. macOS **locked use** can temporarily unlock after the Mac locks, only for an active trusted Computer Use turn, with displays covered and relock on local input. Invoke with `@Computer` or `@AppName`. Cannot automate terminal apps or ChatGPT itself, and cannot approve OS security prompts. GUI edits may not appear in the review pane until saved and tracked. — [Computer Use](https://developers.openai.com/codex/computer-use)
- Windows Computer Use shipped 2026-05-29 (26.527). Locked / remote computer use on macOS shipped 2026-05-21 (26.519). — [Changelog, 2026-05-29 and 2026-05-21](https://developers.openai.com/codex/changelog)
- Built-in browser is desktop-only (not CLI or IDE). Separate profile from the user’s regular browser. Split view and full view; Cmd/Ctrl+Shift+B toggles. Address bar searches its own history, else Google. Computer Use can operate it via `@Browser`. Preview flow: start the dev server in the integrated terminal or a local-environment action, open the local route, review beside the diff, leave comments, ask the chat to address them. **Annotate** mode: click an element or drag a region, comment, optionally **Adjust** font/text/spacing/color and preview before sending. Developer mode (Settings > Browser) enables full CDP after an extra approval; admins can disable it. ChatGPT asks before using a site unless allowed; cannot automate file uploads in the built-in browser. Prefer the built-in browser over Computer Use for local web apps. Chrome/Edge/Brave/Opera/Vivaldi extension is the path into an existing browser profile. — [Browser](https://developers.openai.com/codex/browser)
- 2026-08-25: in the built-in browser, ChatGPT Work and Codex can use website-provided tools (WebMCP). At that date, GPT-5.6 Sol or Terra, not Luna, and not Enterprise or Edu. — [Changelog, 2026-08-25](https://developers.openai.com/codex/changelog)
- Appshots: screenshot plus available text of the frontmost window. macOS: both Command keys, shipped 2026-05-21. Windows: both Alt keys, shipped 2026-09-11. Voice screen context on macOS can take an appshot (“Take a look at this”), including accessible text outside the visible scroll area. — [Changelog, 2026-05-21 and 2026-09-11](https://developers.openai.com/codex/changelog); [ChatGPT Voice](https://developers.openai.com/codex/features/voice)
- Sites (public beta as of the fetched page; preview in the app on 2026-06-02): create/host/share websites and web apps from a prompt or a compatible local project. Every deployment URL is production; save-without-deploy is the review step. Local projects store linkage in `.openai/hosting.json`. Desktop Sites management is in the app; CLI and IDE have no Sites management view. — [Sites](https://developers.openai.com/codex/sites); [Changelog, 2026-06-02](https://developers.openai.com/codex/changelog)
- Integrated terminal: browser docs tell you to start the dev server there. 2026-06-01 (26.601) added **Default terminal location** so the terminal shortcut and environment actions open in the bottom panel or the right panel. — [Browser](https://developers.openai.com/codex/browser); [Changelog, 2026-06-01](https://developers.openai.com/codex/changelog)

#### Plugins, skills, automations, memory, voice, notifications, multi-agent, permissions

- A skill is instructions plus resources. A plugin is an installable bundle of skills, MCP servers (optional custom UI), and Codex lifecycle hooks. ChatGPT and Codex share one plugin directory. Codex invokes skills with `$`; ChatGPT uses `@`. Desktop scheduled-task prompts can use `$skill-name`. Record & Replay can turn a demonstrated workflow into a skill (macOS; Computer Use required; expanded to EU/UK/Switzerland 2026-07-31). — [Skills & Plugins](https://developers.openai.com/codex/skills-and-plugins); [Scheduled tasks](https://developers.openai.com/codex/automations); [Changelog, 2026-07-31](https://developers.openai.com/codex/changelog)
- 2026-08-11: desktop app can import instructions, settings, skills, plugins, projects, and recent work from Claude Code, Claude Cowork, and Cursor, with optional automatic updates under Settings > Import. CLI `/import` covers Claude Code and Cursor setup and recent chats, not the full desktop import list. — [Changelog, 2026-08-11](https://developers.openai.com/codex/changelog)
- Scheduled tasks in the desktop app can use local projects, either the project directory or an isolated worktree. The computer must stay on and the app running for local files. **Scheduled** sidebar view is an inbox; unread indicator for runs that need attention. Standalone tasks start a new chat per run. A task scheduled inside a chat returns to that chat (minute intervals, or daily/weekly). Custom cadence via RFC 5545 RRULE. They run unattended with default sandbox settings and `approval_policy = "never"` when org policy allows; otherwise they fall back to the selected permission mode. Event triggers (Gmail, Slack, GitHub) are web/mobile only and are **not** available in the desktop app, CLI, or IDE extension (shipped 2026-08-25 for web/mobile). — [Scheduled tasks](https://developers.openai.com/codex/automations); [Changelog, 2026-08-25](https://developers.openai.com/codex/changelog)
- Launch-day automations (2026-02-02) already landed results in a review queue. OpenAI’s “what’s next” then said cloud-based automation triggers were still being built so Codex could run when the computer is not open. — [Introducing the Codex app](https://openai.com/index/introducing-the-codex-app/)
- Local Codex memories are off by default, separate from ChatGPT web memory. Desktop: Settings > Personalization > Enable memories, and `/memories` per chat (use existing memories vs contribute future ones). Files under `~/.codex/memories/`. Generation is background, skips active/short sessions, redacts secrets, and can skip when rate-limit remaining is below a threshold. `memories.disable_on_external_context` can exclude chats that used MCP, web search, or tool search. — [Memories](https://developers.openai.com/codex/customization/memories)
- Computer History (macOS, opt-in, requires Memories): activity across allowed apps and websites becomes memories and a timeline. Launched 2026-08-13 for Pro, Business, Enterprise, excluding EEA/Switzerland/UK. Those regions added 2026-08-20, still off by default, admin-gated for Business/Enterprise. — [Memories](https://developers.openai.com/codex/customization/memories); [Changelog, 2026-08-13 and 2026-08-20](https://developers.openai.com/codex/changelog)
- ChatGPT Voice (GPT-Live) in Chat, Work, and Codex in the desktop app, Plus/Pro/Business/Edu/Enterprise. Shipped 2026-07-23 (26.715). Start voice chat / Start new voice chat. Can interrupt, steer, start separate tasks, and jump to another Codex task that supports voice. Only one voice chat at a time across the app. Voice in existing Codex tasks was still rolling out on the fetched page. Dictation is a separate “speech to prompt text” path and was a launch feature (2026-02-02). — [ChatGPT Voice](https://developers.openai.com/codex/features/voice); [Changelog, 2026-07-23](https://developers.openai.com/codex/changelog); [Introducing the Codex app](https://openai.com/index/introducing-the-codex-app/)
- Desktop notifications: never / only in background / always for turn completion; separate toggles for permission and question notifications. **Activity** (bell; Cmd+Option+U / Ctrl+Alt+U): unread, running, or waiting. Filters can include Work, Chat, Pinned, Scheduled. A floating pet can show Running, Needs input, Ready, or Blocked. Activity view added 2026-07-30. — [Notifications](https://developers.openai.com/codex/notifications); [Changelog, 2026-07-30](https://developers.openai.com/codex/changelog)
- Subagent workflows are on by default in current local Codex releases. The app shows each subagent thread; you can open it from the main thread and ask Codex to steer, stop, or close threads. Subagents inherit the parent’s sandbox and the permission mode selected under the composer. Built-ins: `default`, `worker`, `explorer`. Custom agents are TOML files in `~/.codex/agents/` or `.codex/agents/`. They consume extra tokens. Local clients delegate when asked or when `AGENTS.md` / skill instructions request it; proactive delegation is described for ChatGPT Work Ultra, not as the desktop default. — [Subagents](https://developers.openai.com/codex/agent-configuration/subagents)
- 2026-05-29 changelog: thread coordination for local projects and worktrees, including separate background threads when explicitly requested; stable identicons for background subagents. 2026-07-09: task and subagent activity made easier to follow. — [Changelog, 2026-05-29 and 2026-07-09](https://developers.openai.com/codex/changelog)
- Permission control sits under the composer. **Ask for approval** is always available. **Approve for me** (Auto-review in settings) and **Full access** must be turned on under Settings > General > Permissions before they appear; enabling does not select them. Org policy can disable a mode. Sandbox and approvals are separate: Approve for me does not widen the sandbox. Common sandbox modes: `read-only`, `workspace-write` (described as the default low-friction local mode), `danger-full-access`. Approval policies: `on-request` (ask when leaving the sandbox), `never`. `approvals_reviewer` is `user` or `auto_review`. Full access is `danger-full-access` plus `never`. macOS sandbox is Seatbelt; Windows uses the native Windows sandbox in PowerShell; Linux/WSL2 uses bubblewrap. — [Permissions](https://developers.openai.com/codex/permission-modes); [Sandbox](https://developers.openai.com/codex/sandboxing)
- Other dated interaction traits from the changelog, not re-verified on a current settings page: mid-turn steering (2026-02-05, app 26.205); follow-up queue-by-default (2026-02-08, 26.208); conversation forking (2026-02-12, 26.212); Goal mode no longer experimental in the app, IDE, and CLI (2026-05-21); search of past app threads includes conversation content and Git branch names (2026-05-29); macOS read-only snapshot sharing of a local Codex thread (2026-08-20), not live-updating. — [Changelog](https://developers.openai.com/codex/changelog)

#### Relationship to the CLI

- Official app-server docs say `codex app-server` is the interface Codex uses to power rich clients, with the VS Code extension as the example. They do **not** say the desktop app is that client. The command is described as experimental and not supported for production workloads (changelog 2026-09-05, after deprecating `codex mcp-server` on 2026-08-24). — [Codex App Server](https://developers.openai.com/codex/app-server); [Changelog, 2026-09-05](https://developers.openai.com/codex/changelog)
- What official sources do say the app shares with the CLI: session history and configuration (launch post); open-source sandbox (launch post and sandbox docs); skills usable in app, CLI, and IDE (launch post); MCP settings adopted across surfaces is claimed by a third-party article citing older `/codex/app/features` URLs, not re-confirmed in the pages fetched today. CLI lacks the desktop Projects view, Scheduled UI, Sites UI, and built-in browser. — [Introducing the Codex app](https://openai.com/index/introducing-the-codex-app/); [Projects and chats](https://developers.openai.com/codex/projects); [Scheduled tasks](https://developers.openai.com/codex/automations); [Sites](https://developers.openai.com/codex/sites); [Browser](https://developers.openai.com/codex/browser)

### Inferences

- The durable interaction model a competitor would be copying is not “a chat window on the CLI.” It is a supervisor layout: many chats stay visible, each chat has an execution place (local checkout, worktree, or cloud), and completed work returns to a diff the user can comment on, stage, or revert without leaving the app.
- Terminology drifted from “threads” (Feb 2026 launch and changelog) to “chats” (current projects doc), with legacy anchors still named `thread` / `task`. Treat them as the same object unless a page distinguishes ChatGPT chats from Codex chats.
- After 2026-07-09, desktop Codex UX and general ChatGPT desktop UX (Work, Sites, Voice, Pets, plugins) share one shell. Feature lists that ignore that split will mix coding-agent traits with knowledge-work traits.

### Gaps

- No official sentence found that the desktop app process launches `codex app-server` or embeds the CLI. Do not treat that as established.
- Did not fetch the current Linux app page. Linux was announced as a preview on 2026-08-11 for Ubuntu/Debian/Fedora, x64 and ARM64. No later changelog entry in the fetched log promoted it to GA. — [Changelog, 2026-08-11](https://developers.openai.com/codex/changelog)
- Did not confirm whether the desktop app UI can select Amazon Bedrock or an API key. Bedrock was announced for Codex on 2026-06-01 (“run Codex locally” with AWS auth) without a surface list in the entry read. — [Changelog, 2026-06-01](https://developers.openai.com/codex/changelog)
- Keyboard shortcut tables in third-party writeups (for example Cmd+J for terminal) were not checked against the current commands reference.
- “Webhook” as a desktop automation trigger appears in a 2026-04-08 article updated 2026-09-30, but the current official scheduled-tasks page says event triggers are not available in the desktop app. — [Daniel Vaughan](https://codex.danielvaughan.com/2026/04/08/codex-desktop-automations/); contradicted by [Scheduled tasks](https://developers.openai.com/codex/automations)

## Which features require OpenAI cloud services versus running locally?

### Takeaway

Local and Worktree chats execute on the computer (files, Git, sandbox, integrated terminal, built-in browser, computer use). Model turns still require a signed-in ChatGPT account and OpenAI-hosted models. Cloud placement, Sites hosting, automatic GitHub/GitLab reviews, and ChatGPT Work’s cloud browser are OpenAI-hosted. Local scheduled tasks die if the app or machine is off; they are not cloud jobs.

### Cited Findings

- App setup requires signing in with a ChatGPT account. — [ChatGPT desktop app](https://developers.openai.com/codex/app)
- Composer **Work in** menu: **This computer** or **Cloud**, plus a separate **Worktree** control for local Git projects. Local and Worktree chats run on the computer. A cloud task uses a published environment; the computer’s local files, processes, browser sign-ins, and VPN are not transferred. File changes in a cloud task do not update the reusable environment. — [Codex environments](https://developers.openai.com/codex/environments/modes)
- Sandbox applies to spawned commands in desktop, CLI, and IDE, using OS enforcement (Seatbelt, Windows sandbox, bubblewrap). That is local execution, not a cloud container. — [Sandbox](https://developers.openai.com/codex/sandboxing)
- Worktrees, handoff, `$CODEX_HOME/worktrees`, and `.worktreeinclude` are local Git operations. Remote/mobile does not run the worktree on the phone; Remote controls the connected computer. — [Worktrees](https://developers.openai.com/codex/environments/git-worktrees)
- Desktop scheduled tasks that need local files require the computer on and the app running. They use the local sandbox. Event-triggered tasks are cloud-side and not available in the desktop app. Team Tasks run in the cloud via a team service account. — [Scheduled tasks](https://developers.openai.com/codex/automations)
- Computer Use, locked use, appshots, and the built-in browser operate on the local machine (or, for remote control, on the connected desktop host). ChatGPT Work’s browser on web/mobile is a separate cloud computer and does not use the local browser profile. — [Computer Use](https://developers.openai.com/codex/computer-use); [Browser](https://developers.openai.com/codex/browser)
- Local memories and Computer History are on-device stores (`~/.codex`), but memory generation uses a model (`memories.extract_model` / `consolidation_model`) and can be skipped when Codex rate-limit remaining is low. — [Memories](https://developers.openai.com/codex/customization/memories)
- Sites hosting, D1/R2 storage, deployment URLs, and analytics are OpenAI-hosted. Local source can stay in a Git project; publishing is a cloud step. Sites does not support data residency at launch. — [Sites](https://developers.openai.com/codex/sites)
- Automatic PR review with the ChatGPT Codex connector is a cloud review and does not require the user to create a cloud environment. Comments appear on GitHub and in Code Review. Local `/review` and the review pane run against the local Git checkout. — [Code review](https://developers.openai.com/codex/code-review)
- Local computer access with Work Cloud: OpenAI’s cloud coordinates the conversation; sandbox rules depend on whether a step runs in a cloud container or on the connected computer. Desktop browser site rules do not automatically apply to cloud browsers. — [Sandbox](https://developers.openai.com/codex/sandboxing); [Projects and chats](https://developers.openai.com/codex/projects)
- Voice is a cloud speech product (GPT-Live) driving local or connected-host tasks. — [ChatGPT Voice](https://developers.openai.com/codex/features/voice)
- Subagents in local Codex clients run as local agent threads and inherit the local sandbox. ChatGPT Work subagents run in a hosted environment. — [Subagents](https://developers.openai.com/codex/agent-configuration/subagents)
- 2026-02-02 launch post: default local behavior is edit in the working folder or branch, cached web search, and ask before elevated commands such as network access. Cached web search is an OpenAI-maintained index (documented 2026-01-28 for CLI and IDE; the launch post states the same default for the app). — [Introducing the Codex app](https://openai.com/index/introducing-the-codex-app/); [Changelog, 2026-01-28](https://developers.openai.com/codex/changelog)
- A 2026-02-27 review claimed “All Codex app agents run in cloud containers” and that code is uploaded for every task. That conflicts with the launch post’s local sandbox description and with the current Local/Worktree docs. — [Awesome Agents review, 2026-02-27](https://awesomeagents.ai/reviews/review-openai-codex-app/); contradicted by [Introducing the Codex app](https://openai.com/index/introducing-the-codex-app/) and [Codex environments](https://developers.openai.com/codex/environments/modes)

### Inferences

- “Runs locally” in this product means the workspace, sandbox, and GUI tools are on the machine. It does not mean the model runs locally. A competing local-first app would be copying the execution boundary, not the inference path.
- The cloud/local split is a per-chat placement choice, not a property of the app. Mixing them up is a documented failure mode: existing tasks do not gain local-file access just because sync is on, and a cloud continuation cannot see the computer’s files.

### Gaps

- No current official page fetched that states whether desktop Codex can run fully offline after sign-in, or which model calls are mandatory on every turn.
- No confirmation that desktop Codex supports API-key or Bedrock auth the way the CLI does.
- Did not fetch Codex Cloud environment docs, so cloud image/setup details are not inventoried here beyond the modes page.

## What is widely regarded as the best part of the Codex desktop experience, and what is weak?

### Takeaway

Across the launch post and 2026 reviews that describe observable behavior, the praised core is parallel chats isolated by Git worktrees, with an in-app diff review queue so the user supervises instead of living in one terminal session. Early “macOS-only” and “everything executes in the cloud” criticisms are outdated or contradicted. No independent September 2026 review of the merged ChatGPT desktop app was found; remaining weaknesses that official docs still state are usage-limit dependence, Windows computer use taking the foreground, and local automations that stop when the app is closed.

### Inferences

- The repeated “best part” is the supervision loop (parallel isolated chats → one review surface), not any single model. Reviews that praise the app and reviews that criticize limits are describing that same loop.
- Weakness claims must be dated. Platform exclusivity and “cloud-only execution” should not be carried forward as September 2026 facts. Limit pressure and online model dependence are the complaints that official docs still make plausible, because local runs still need a ChatGPT sign-in and scheduled local work still needs the app open.
