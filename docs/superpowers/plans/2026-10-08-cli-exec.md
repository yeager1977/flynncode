# CLI exec (non-interactive run mode) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring `opencode run` to Codex-`exec` parity for scripts and CI: progress on stderr, final answer on stdout, `--json` JSONL event stream, `--output-schema` structured output, and resume-by-session for two-stage pipelines.

**Architecture:** No server or protocol changes. All work is confined to the CLI layer (`packages/flynncode/src/cli/cmd/run.ts` + `packages/flynncode/src/cli/ui.ts`): fix the stdout/stderr split in the existing non-interactive `execute()`/`loop()`, add envelope JSONL events around the existing `emit()` path, and wire the already-supported `PromptInput.format` (`json_schema`, implemented in `packages/flynncode/src/session/prompt.ts` via the `StructuredOutput` tool) through a new `--output-schema` flag. Session resume reuses the existing `--session`/`--continue` machinery; the plan only adds machine-readable session-ID discovery.

**Tech Stack:** Bun + TypeScript monorepo (`packages/flynncode`), yargs flags, existing SDK v2 client (`@opencode-ai/sdk/v2`), Effect services unchanged, `bun:test` subprocess harness (`test/lib/cli-process.ts` + `test/cli/run/run-process.test.ts`).

## Global Constraints

- Backends self-hosted or user-owned only; vendor-hosted clouds, Sites hosting, and voice products stay OUT. (This plan touches no backends at all.)
- Do not use the `any` type.
- Never alias imports (`import { foo as bar }`), never use star imports (`import * as Foo`).
- Prefer dynamic imports for heavy modules only needed in selected code paths, destructured near the top of the narrowest scope that needs them.
- Prefer `const` over `let`; ternaries or early returns instead of reassignment; no `else` statements, prefer early returns.
- In Effect generators, bind services to named variables before calling methods; do not use nested service yields such as `yield* (yield* Foo.Service).bar()`.
- Use `Bun.file()` for file reads.
- Tests run from package dirs like `packages/flynncode`, never from repo root.
- Always run `bun typecheck` from `packages/flynncode` after code changes, never `tsc` directly.
- Branch name: at most three words, hyphens, no slashes or type prefixes (e.g. `cli-exec-parity`).
- Commits and PR titles use conventional style `type(scope): summary` with types `feat`, `fix`, `docs`, `chore`, `refactor`, `test`.
- Default branch is `dev`.

## Current-state map (verified 2026-10-08)

- `packages/flynncode/src/cli/cmd/run.ts` — `RunCommand` (`run [message..]`). Non-interactive path is `execute(sdk)` → `loop(client, events)`. `--format json` switches `emit()` to write one JSON object per line to **stdout** (`process.stdout.write(JSON.stringify(...) + EOL)`); event types today: `tool_use`, `step_start`, `step_finish`, `text`, `reasoning`, `error`. Every JSON event already carries `type`, `timestamp`, `sessionID`.
- `packages/flynncode/src/cli/ui.ts` — `UI.println`/`UI.print`/`UI.error`/`UI.empty` all write to **stderr**. So tool inline progress, permission notices, agent-fallback warnings, and share URLs already go to stderr. Final assistant text goes to **stdout** via `process.stdout.write(text + EOL)` when not a TTY.
- Known stdout-purity violations in default (non-JSON) mode: `run.ts:777` writes `Thinking: ...` to **stdout** when not a TTY (`process.stdout.write(line + EOL)`); TTY branch correctly uses `UI` (stderr). No other stdout writes exist in the non-interactive path.
- `PromptInput.format` (`packages/flynncode/src/session/prompt.ts:1625-1647`) already supports `SessionV1.Format` including `{ type: "json_schema", schema }`. The runner injects a `StructuredOutput` tool (`createStructuredOutputTool`, line 1692), captures output into `handle.message.structured`, and errors with `StructuredOutputError` if the model never calls it. `PromptPayload` (`packages/flynncode/src/server/routes/instance/httpapi/groups/session.ts:70`) is `Struct.omit(SessionPrompt.PromptInput.fields, ["sessionID"])`, so the SDK `session.prompt` call already accepts `format` — the CLI simply never sends it.
- Resume exists (`--session`/`--continue`/`--fork` in `run.ts:456-533`) but the session ID is undiscoverable for scripts: default mode prints nothing machine-readable, JSON mode only repeats `sessionID` per event with no explicit start record.
- No `--json` shorthand exists; only `--format json`.
- Test harness: `test/lib/cli-process.ts` (`RunOpts`, `opencode.run`, `parseJsonEvents`, `expectExit`) and `test/cli/run/run-process.test.ts` cover stdout text, `--format json` shapes, and stderr permission notices.

### Task 3: `--output-schema` structured output for CI

**Files:**
- Create: `packages/flynncode/src/cli/cmd/run/output-schema.ts` (parse + validate + extract helpers)
- Modify: `packages/flynncode/src/cli/cmd/run.ts` (add `--output-schema` flag, pass `format` to `session.prompt`/`session.command`, print structured result)
- Test: `packages/flynncode/test/cli/run/run-process.test.ts` (append new cases)

**Interfaces:**
- Consumes: `SessionV1.Format` (`{ type: "json_schema", schema }` — read the exact field shape from the installed `@opencode-ai/schema/session-v1` `Format`/`OutputFormatJsonSchema` definitions before writing code; the prompt runner at `packages/flynncode/src/session/prompt.ts:1349-1356` reads `lastUser.format.schema`), SDK `session.prompt({ format })` (already accepted via `PromptPayload`), `WithParts.structured` (set at `prompt.ts:1394-1399`; fall back to the completed `StructuredOutput` tool part's parsed input when `structured` is absent).
- Produces:
  - `parseOutputSchema(raw: string) => Record<string, string | number | boolean | null | unknown[] | object>` — `raw` starting with `@` reads `Bun.file(raw.slice(1))`, otherwise parses `raw` inline as JSON; rejects non-object schemas, empty input, and missing files with a `CLI error → process.exit(1)` diagnostic on stderr.
  - `readStructuredResult(message: SessionV1.WithParts) => unknown` — returns `message.structured` when present, else the completed `StructuredOutput` tool part output, else `undefined`.
  - CLI contract: default mode prints pretty-printed JSON of the structured result to **stdout** (and nothing else); `--json` mode emits it as a `{ type: "structured_output", output }` JSONL event on stdout; model failure to produce structured output exits nonzero with the `StructuredOutputError` message on stderr.
