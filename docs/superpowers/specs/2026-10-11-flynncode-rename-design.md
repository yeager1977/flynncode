# Flynncode Rename — Design

Date: 2026-10-11
Status: Approved
Branch: `rename-flynncode` (based off `dev`)

## Goal

Flynncode is diverging from upstream opencode. This makes the fork's identity real in
the code: npm scope, CLI command, runtime data dirs, desktop branding, and docs all
become flynncode. Upstream compatibility is preserved where it matters: legacy
opencode data is imported once rather than abandoned, `OPENCODE_*` env flags keep
working, and external upstream services keep functioning.

## Decisions (agreed with user)

- Rename now: npm scope `@opencode-ai/*` → `@flynncode/*`, private package
  `opencode` → `flynncode` including the CLI bin, desktop/UI branding.
- CLI binary becomes `flynncode`, storing config/sessions/auth in new flynncode dirs
  with a one-time import from legacy opencode dirs.
- Service URLs (`opencode.ai`, `api.opencode.ai`, GitHub owner/repo, brew tap) are
  parameterized behind a constants module; defaults keep today's upstream values
  until Flynncode services exist.
- Desktop publish identity: `flynncode`-based defaults, env-overridable.
- Docs: brand-level updates to root README, AGENTS.md, CONTRIBUTING.md, SECURITY.md.
  Translated READMEs and upstream prose are a later pass.

## Pass 1 — Workspace rename

- All `@opencode-ai/*` package names → `@flynncode/*` (short package names unchanged:
  `@flynncode/core`, `@flynncode/sdk`, `@flynncode/app`, …).
- `packages/opencode/` → `packages/flynncode/`; package name `opencode` → `flynncode`;
  bin key `opencode` → `flynncode`.
- Update all `workspace:*` refs, tsconfig paths/aliases, turbo config, build scripts
  (`packages/sdk/js/script/build.ts`), GitHub Actions workflows.
- Lockfile regenerated by `bun install` from package.json edits, never hand-edited.
- Deliberately untouched: third-party packages `@gitlab/opencode-gitlab-auth`,
  `opencode-poe-auth`, `opencode-gitlab-auth`; the vendored
  `@opencode-ai/client-*.tgz` reference (upstream artifact, addressed in a follow-up).

## Pass 2 — Runtime identity & one-time import

- Global dirs become `~/.config/flynncode`, `~/.local/share/flynncode`,
  `~/.cache/flynncode` (via `Global.Path` and related modules). Project-local config
  dirs become `.flynncode/` with config files `flynncode.json` / `flynncode.jsonc`.
- One-time import module in the core global layer:
  - On first run of `flynncode`, if legacy `~/.config/opencode` /
    `~/.local/share/opencode` exist and the marker
    `~/.local/share/flynncode/imported` is absent, copy config, auth, and session
    data into the flynncode dirs, then write the marker.
  - Marker is written only after a fully successful copy; import failures log a
    warning, are non-fatal, and retry on the next run.
  - Import is non-destructive: legacy dirs remain usable by upstream `opencode`.
- Project-local `.opencode/` directories continue to be discovered during the
  transition, treated as read-only legacy input; `.flynncode/` always wins. This shim
  is removed in a later pass.
- Env flags: `OPENCODE_*` remain recognized (back-compat); `FLYNNCODE_*` is the
  documented preferred prefix, aliased in the existing `Flag` module.

## Pass 3 — Desktop/UI branding

- `productName`: "OpenCode" / "OpenCode Dev" / "OpenCode Beta" →
  "Flynncode" / "Flynncode Dev" / "Flynncode Beta".
- Desktop appId `ai.opencode.desktop` → `ai.flynncode.desktop`; URL scheme
  `opencode` → `flynncode`; deb/rpm package name `flynncode`.
- Electron `publish` points at owner/repo defaults `flynncode/flynncode`,
  overridable via env in CI. Desktop-entry paths in the existing test are updated to
  match.
- Window titles and "OpenCode" UI strings across app, session-ui, web, tui →
  "Flynncode". Icon artwork is unchanged in this pass.

## Pass 4 — Service URL parameterization

- New core module, `ServiceEndpoints`: constants for console, auth, api, share base
  URLs, the GitHub owner/repo used by the CLI agent installer, and the brew tap
  name. Defaults preserve today's upstream values.
- Every literal call site (`opencode.ai`, `api.opencode.ai`, `anomalyco/tap/opencode`,
  share base URLs) imports from this module instead.
- The `opencode` provider id and `opencode/*` model ids remain untouched — they are
  provider-side identifiers, not branding.

## Pass 5 — Docs

- Brand-level updates to root `README.md`, `AGENTS.md`, `CONTRIBUTING.md`,
  `SECURITY.md`: command name, package scope, product name, plus a short note that
  flynncode imports existing opencode data on first run.
- Translated `README.*.md` files and upstream-specific prose are deferred.

## Verification

- Per pass: `bun typecheck` and tests from affected package dirs (never repo root).
- Grep audits: no remaining `@opencode-ai/` references; known allowed residue limited
  to third-party package names, provider ids, the vendored client tarball, and
  legacy-import handling.
- End-to-end smoke in a temporary `$HOME`: `flynncode --help` runs; a fake legacy
  opencode dir is imported (files copied, marker written, second run is a no-op); TUI
  boots in tmux.

## Out of scope

- New icon/logo artwork; translated READMEs; removing the `.opencode/` legacy
  fallback; replacing upstream service endpoints with Flynncode services; publishing
  npm packages under the new scope.
