Applies several exact string replacements to one file in a single call.

Usage:
- Prefer this over several `edit` calls when making multiple changes to the same file.
- Edits are applied in order, and each edit operates on the result of the previous one. Plan them so earlier edits do not remove text that later edits need to match.
- The call is atomic: if any edit fails (text not found, more than one match without `replace_all`, or `old_string` equal to `new_string`), the file is not changed and the error names the failing edit by its 1-based position.
- Each edit takes `old_string`, `new_string`, and an optional `replace_all` to replace every occurrence (useful for renaming).
- Matching rules are the same as the `edit` tool; include enough surrounding context in `old_string` to make it unique.
- To create a new file, use a nonexistent `file_path` and make the first edit's `old_string` empty with the file contents as `new_string`; later edits then apply to that content. An empty `old_string` is not allowed on an existing file.
- When editing text from Read tool output, preserve the exact indentation as it appears after the line number prefix. Never include the line number prefix in `old_string` or `new_string`.
- Only use emojis if the user explicitly requests it.
