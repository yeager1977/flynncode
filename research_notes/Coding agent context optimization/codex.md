# How OpenAI Codex economizes context and tokens (CLI, desktop app, and cloud agents)

State of the world as of 2026-10-19. All GitHub source citations are from `openai/codex` branch `main` as retrieved 2026-10-19 (unversioned head). Key context for temporal interpretation: Codex is no longer a standalone "Codex-only" ecosystem — as of 2026 it is a surface of ChatGPT Work ("Codex CLI, IDE extension, and cloud automation"), with docs at learn.chatgpt.com (mirrored Markdown by appending `.md`) and OpenAI model documentation at developers.openai.com. Current model generation: GPT-6 Astra / GPT-6 Sol / GPT-6 Luna, and GPT-6.1 Sol (the config example default in the config reference); GPT-5.5 retires from Codex for ChatGPT sign-in on Oct 14, 2026 — [Speed doc](https://learn.chatgpt.com/docs/agent-configuration/speed.md), [Doc index](https://learn.chatgpt.com/llms.txt), [Config reference](https://learn.chatgpt.com/docs/config-file/config-reference.md).

Legend: [Doc] = official OpenAI docs/blog/system card; [Source] = open-source repo code; [Community] = third-party/blog/issue analysis (issues authored by OpenAI staff are treated as semi-official and noted as such).

## What occupies context per turn (system prompt, AGENTS.md, tool schemas, reasoning summaries, JIT loading)

### Takeaway
Codex's per-turn context is composed at turn boundaries from: model-owned base instructions (per-model, catalog-overridable), an AGENTS.md instruction chain scoped global → project root → cwd (≤32 KiB default), tool schemas gathered into a startup "tool catalog," harness-injected short messages (token-budget reminders, recovery guidance), and a persistent "world state" that survives compaction windows. Loading is hierarchical rather than fully just-in-time: AGENTS.md is flattened per run (rebuilt every session, no cache), skills are the JIT exception (a budgeted catalog overview with full skill text inserted only when selected via `/skills`).

### Cited Findings
- Base instructions are now model-owned and resolved per model from a catalog with bundled defaults; each accessor "selects and resolves only the requested message family" (instructions template, approvals, permissions, collaboration modes, multi-agent, auto-review, tool descriptions, token-budget reminders). — [Source: codex-rs/prompts/src/model_messages.rs](https://github.com/openai/codex/blob/main/codex-rs/prompts/src/model_messages.rs), accessed 2026-10-19
- `model_instructions_file` is a config key: "Replacement for built-in instructions instead of `AGENTS.md`"; `personality` is deprecated but "none omits the built-in Personality section from model instructions" — i.e., the system prompt has sections, one of which is Personality. — [Doc: Config reference](https://learn.chatgpt.com/docs/config-file/config-reference.md), fetched 2026-10-19
- AGENTS.md chain: Codex builds the instruction chain once per run/session, precedence: (1) global `~/.codex/AGENTS.override.md` else `AGENTS.md` (first non-empty file only); (2) project root (typically Git root) down to cwd, checking `AGENTS.override.md`, `AGENTS.md`, then `project_doc_fallback_filenames`, at most one file per directory; (3) merge order is concatenation root-down with blank lines, so files closer to cwd appear later and "override earlier guidance because they appear later in the combined prompt." Codex skips empty files and stops once the combined size reaches `project_doc_max_bytes` (32 KiB by default). — [Doc: Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md.md), fetched 2026-10-19
- Source-code confirmation of the same algorithm: project root found by walking up to `project_root_markers` (default `.git`); every AGENTS.md from project root down to cwd is concatenated in that order; traversal stops at the project root; a shared budget (`project_doc_max_bytes`) is decremented across all environments and files are truncated at the budget edge. When multiple project environments contribute, output is labeled "for `{environment}` with root `{cwd}`" once per group. `AGENTS.override.md` is the preferred local override filename. — [Source: codex-rs/core/src/agents_md.rs](https://github.com/openai/codex/blob/main/codex-rs/core/src/agents_md.rs)
- Tool schemas: a startup "tool catalog" is built with only 1 s default wait for optional MCP servers (`mcp_optional_startup_grace_ms` defaults to `1000`); tool descriptions are resolved from the model catalog (e.g., an async user-input tool description ships as bundled default text and can be catalog-overridden per model). — [Doc: Config reference](https://learn.chatgpt.com/docs/config-file/config-reference.md); [Source: model_messages.rs](https://github.com/openai/codex/blob/main/codex-rs/prompts/src/model_messages.rs)
- Skills are the just-in-time mechanism: `skills.max_context_tokens` gives the available-skills catalog a token budget defaulting to 2% of the model's context window, explicitly capped at 10,000 tokens; `/skills` "inserts the selected skill context so the next request follows that skill's instructions." — [Doc: Config reference](https://learn.chatgpt.com/docs/config-file/config-reference.md); [Doc: Developer commands](https://learn.chatgpt.com/docs/developer-commands.md?surface=cli)
- Harness-injected messages have hard size bounds: the token-budget reminder template reads "Your context window is nearly exhausted (only {n_remaining} tokens remaining) and will be automatically reset for you soon. Once reset, message items in current context window will be cleared in the new window, but notes and history items will be persistent across windows."; content-filter recovery guidance is capped at 512 bytes. — [Source: model_messages.rs](https://github.com/openai/codex/blob/main/codex-rs/prompts/src/model_messages.rs)
- Reasoning summaries are a first-class, tunable context element: `model_reasoning_summary = auto | concise | detailed | none` selects reasoning summary detail or disables summaries entirely; `model_verbosity = low | medium | high` controls final-answer verbosity. — [Doc: Config reference](https://learn.chatgpt.com/docs/config-file/config-reference.md)
- Memories are off by default (`features.memories` off by default; `memories.use_memories` defaults true only while memory generation is enabled, and disabled-on-external-context options exist), so memory injection is opt-in context. — [Doc: Config reference](https://learn.chatgpt.com/docs/config-file/config-reference.md)
- A `codex debug prompt-input` CLI subcommand "renders the exact model-visible prompt input list as JSON. Use this when debugging instruction discovery, session context, or prompt construction" — official confirmation that the per-turn context is exactly: initial context (environment) + instructions chain + tool catalog. — [Doc: Developer commands](https://learn.chatgpt.com/docs/developer-commands.md?surface=cli)
- The "world state" concept is structural in the core crate: compaction rebuilds history from a world-state snapshot plus retained items; notes/history persist across compaction windows while "message items in current context window will be cleared." — [Source: codex-rs/core/src/compact.rs](https://github.com/openai/codex/blob/main/codex-rs/core/src/compact.rs); [Source: model_messages.rs reminder template](https://github.com/openai/codex/blob/main/codex-rs/prompts/src/model_messages.rs)

### Inferences
- The layering is "flattened-once, budgeted" rather than lazy: everything in the AGENTS.md chain and bounded tool catalog enters the first turn; only skills are opened on demand. This differs from agents that attach file contents lazily per tool call: Codex pays a fixed instruction-chain tax per session instead of per-turn exploration tokens.
- The 32 KiB AGENTS.md cap plus "split instructions across nested directories" guidance implies OpenAI expects most repos to stay under roughly 8k tokens of standing instructions, with gitignore-style scoping delegated to the directory tree.
- Codex's "notes and history items persist across windows" design (visible in the reset reminder and the world-state baseline passed to compaction) is the same idea as an always-surviving `AGENTS.md`/memory layer living inside the harness instead of the model's context window.

### Gaps
- Exact token size of the current (GPT-6.x-era) base instructions: not found in fetched sources; base prompts are per-model catalog values, and I did not enumerate `codex-rs/prompts/templates/` per-model files. The 2025-era flat `codex-rs/core/prompt.md` no longer exists at that path.
- Whether reasoning-summary items count against the visible context window / appear in `debug prompt-input` output (Responses API preserves reasoning server-side): unresolved in fetched material.

## AGENTS.md conventions for token efficiency: official starter templates vs community

### Takeaway
Officially, OpenAI prescribes structure and conciseness of the instruction chain but not specific tool substitutions: the official AGENTS.md doc says to keep rules concise and hide formatting/lint work in CI, and ships `/init` to generate a scaffold. The specific token-economy micro-conventions ("avoid cat/head/tail, read in bounded line ranges," "don't run commands from repo root children," budget of tool output) are community/project-authored content — but they are reinforced from the other side: the Codex models are trained with bounded-read behavior (256-line/200-line reads) so the harness never needs to spell it out.

### Cited Findings
- Official guidance for instruction content: "Keep rules concise, explain the behavior to flag and any safe path or exception, and reserve formatting and lint checks for CI" (scoped to Code Review Rules sections, which live in the AGENTS.md closest to the governed code; repo-wide at root, service-specific nested). — [Doc: Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md.md), fetched 2026-10-19
- `/init` slash command: "Generate an `AGENTS.md` scaffold in the current directory. Capture persistent instructions for the repository or subdirectory you're working in" — official-bootstrap of the instruction chain. — [Doc: Developer commands](https://learn.chatgpt.com/docs/developer-commands.md?surface=cli)
- Official doc's structural advice for budget pressure: "Raise the limit or split instructions across nested directories when you hit the cap" (32 KiB default `project_doc_max_bytes`; configurable e.g. 65536 with fallback filenames). — [Doc: Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md.md)
- Discovery/verification is officially documented: instruction chain rebuilt every run with "no cache to clear manually," and auditable via plaintext TUI log or `session-*.jsonl` session logs. — [Doc: Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md.md)
- The docs point users to the community spec site: "Visit the official [AGENTS.md](https://agents.md) website for more information." — [Doc: Custom instructions with AGENTS.md, Next steps](https://learn.chatgpt.com/docs/agent-configuration/agents-md.md)
- Model-side reinforcement of bounded reads: an OpenAI contributor (etraut-openai) on the truncation feature request: "the gpt5-codex model is trained with the 256-line limit in place. It learns during its training that it should not exceed this limit. Model requests: `sed -n '1,256p' file.rs`" — i.e., the model itself asks for bounded reads (roughly 200-256 lines) to avoid filling the context window. — [GitHub issue #5913, 2025-10-29](https://github.com/openai/codex/issues/5913) (staff comment); corroborated by [issue #8982, 2026-01-09](https://github.com/openai/codex/issues/8982): OpenAI staff: "This is model behavior. It tends to read 200 lines at a time to prevent filling the context window unnecessarily. It will read additional lines as needed."
- Community amplification (Codex-specific, 2026): a Codex knowledge-base article recommends adding AGENTS.md "session hygiene" rules (fork sessions at task boundaries) alongside config `tool_output_token_limit = 10000` and a custom compaction prompt, citing the Microsoft context-engineering study line that "pruning plus summarisation beats full history." — [Community: Codex KB, 2026-06-19](https://codex.danielvaughan.com/2026/06/19/less-context-better-agents-efficient-context-engineering-codex-cli-pruning-summarisation-strategy)
- Community cross-agent comparison research (Claude Code vs Codex CLI vs OpenCode vs Amp) documents Codex's compact prompt and 20k-token recent-user-message retention, used as the canonical compact mechanism across agents. — [Community: badlogic gist, Context Compaction Research](https://gist.github.com/badlogic/cd2ef65b0697c4dbe2d13fbecb0a0a5f)

### Inferences
- The "avoid cat/head/tail in favor of Read with offset/limit"-style AGENTS.md lines seen in some repos (including Flynncode's own AGENTS.md) map to Codex as: instructing an already-trained behavior. In Codex the same economy is enforced structurally (output truncation caps + model training), which is why the official AGENTS.md templates don't carry those micro-rules.
- "Avoid running commands from repo root" is likewise community practice (test-suite output economy); nothing equivalent appears in the fetched official docs for the general CLI.

### Gaps
- I did not fetch the historical openai/codex README/AGENTS.md starter template from 2025 (it was replaced by docs); so "which exact lines were in the official 2025 starter" is not verified in this pass.
- No official statement tying AGENTS.md conventions to leaderboard/benchmark-driven prompt trimming was found (see Gap under "Official guidance").

## Compaction: /compact, auto-compact thresholds, what the summary preserves, resume, /status //usage

### Takeaway
Compaction is Codex's central token-economy mechanism and has graduated from harness feature to model feature: `/compact` (manual) and auto-compaction replace most of the history with a "context checkpoint" summary plus up to 20k tokens of recent user messages, re-injecting canonical context; the compaction summary itself is deliberately restricted to progress/decisions/constraints/next-steps/critical data. Since GPT-5.1-Codex-Max (Nov 2025), the model is trained to work across compaction windows ("Memento"-strategy compaction in telemetry), auto-compact triggers from a token limit or window percentage (including a distinct post-turn trigger), hooks can veto compaction, and a server-side "remote compaction v2" path exists via the Responses API. After compaction, `codex resume`/`/resume` reloads transcripts keeping original history intact, with compaction windows tracked via window ids.

### Cited Findings
- `/compact`: "Summarize the visible chat to free tokens... Use after long runs so Codex retains key points without blowing the context window." Expected behavior: "Codex replaces earlier turns with a concise summary, freeing context while keeping critical details." — [Doc: Developer commands](https://learn.chatgpt.com/docs/developer-commands.md?surface=cli)
- The compaction prompt (verbatim, bundled template): "You are performing a CONTEXT CHECKPOINT COMPACTION. Create a handoff summary for another LLM that will resume the task. Include: Current progress and key decisions made; Important context, constraints, or user preferences; What remains to be done (clear next steps); Any critical data, examples, or references needed to continue. Be concise, structured, and focused on helping the next LLM seamlessly continue the work." — [Source: codex-rs/prompts/templates/compact/prompt.md](https://raw.githubusercontent.com/openai/codex/main/codex-rs/prompts/templates/compact/prompt.md), accessed 2026-10-19; the prompt is exported as `SUMMARIZATION_PROMPT` by [codex-rs/prompts/src/compact.rs](https://github.com/openai/codex/blob/main/codex-rs/prompts/src/compact.rs)
- Replacement-history construction in source: recent real user messages are retained up to `COMPACT_USER_MESSAGE_MAX_TOKENS = 20_000` tokens (selected newest-first, preserving original message parts with annotations, dropping images/audio, marking retained sources incomplete); a summary item (`SUMMARY_PREFIX` + last assistant message) is appended last; canonical initial context is re-inserted (headed "before the last real user message") and a world-state baseline is rebuilt. Telemetry tracks compaction with `CompactionStrategy::Memento`, cached/cache-write input tokens, retained image count, and summary token count. Pre-compact and Post-compact hooks can stop compaction; the compaction request selects its own reasoning effort (`RequestEffortUsage::Compaction`). If the compaction call itself overflows the window, the oldest history item is dropped first to preserve the prompt cache. — [Source: codex-rs/core/src/compact.rs](https://github.com/openai/codex/blob/main/codex-rs/core/src/compact.rs)
- Auto trigger knobs: `model_auto_compact_token_limit` ("Token threshold that triggers automatic history compaction (unset uses model defaults)"), `model_auto_compact_token_limit_scope = total | body_after_prefix` ("full active context (total, the default) or only growth after the carried compaction-window prefix"), and `model_post_turn_compact_threshold_percent` ("Percentage of the usable context window that triggers turn-end compaction. Zero disables turn-end compaction"). — [Doc: Config reference](https://learn.chatgpt.com/docs/config-file/config-reference.md)
- Deltas observed in issues (community reverse-engineering of source): with defaults the compaction threshold is 90% of the window (bundled models.json: 272,000-token window for gpt-5.3-codex → 244k trigger, though the model accepts more); on overflow a `fill_to_context_window` path resets the token counter (a 2026-03 bug where custom `model_context_window` broke that); remote compaction posts full history to `/responses/compact`. — [GitHub issue #16068, 2026-03-28](https://github.com/openai/codex/issues/16068)
- Automated compaction is "primarily driven by context pressure" per an OpenAI-community feature request (Aug 2026) proposing idle-session compaction before prompt-cache expiry — still an open feature request, not documented behavior. — [GitHub issue #40924, 2026-08-26](https://github.com/openai/codex/issues/40924)
- Model-side compaction (the big 2025 shift): GPT-5.1-Codex-Max is "our first model natively trained to operate across multiple context windows through a process called compaction, coherently working over millions of tokens in a single task"; "In Codex applications, GPT-5.1-Codex-Max automatically compacts its session when it approaches its context window limit, giving it a fresh context window. It repeats this process until the task is completed." — [OpenAI blog, 2025-11](https://openai.com/index/gpt-5-1-codex-max); [GPT-5.1-Codex-Max System Card, 2025-11-18](https://cdn.openai.com/pdf/2a7d98b1-57e5-4147-8d0e-683894d782ae/5p1_codex_max_card_03.pdf) (Apollo evaluated with compaction enabled on all configurations where any rollout exceeded 100k tokens)
- Provider-level protocol: `model_providers.<id>.capabilities.remote_compaction`: "`unsupported` uses local compaction; `v2` sends compaction triggers through Responses." — [Doc: Config reference](https://learn.chatgpt.com/docs/config-file/config-reference.md)
- The pre-reset nudge is pattern-based: the model receives "Your context window is nearly exhausted ... and will be automatically reset for you soon ... notes and history items will be persistent across windows." — [Source: model_messages.rs](https://github.com/openai/codex/blob/main/codex-rs/prompts/src/model_messages.rs)
- What happens at reset boundary: compaction windows are numbered and ids advanced (`advance_auto_compact_window`), replacement histories keep `CompactedHistoryMetadata` (goal ids, summary, window ids, compaction response id, model hashes). — [Source: compact.rs](https://github.com/openai/codex/blob/main/codex-rs/core/src/compact.rs)
- Resume: `codex resume` (or `/resume`) "Continue an interactive session by ID or resume the most recent chat... Choose the session you want from the saved-session picker. Expected: Codex reloads the selected chat's transcript so you can pick up where you left off, keeping the original history intact." `codex fork` and `codex exec fork <SESSION_ID>` copy a saved session into a new session (branching without touching the original). — [Doc: Developer commands](https://learn.chatgpt.com/docs/developer-commands.md?surface=cli)
- Token-budget display: `/status` "Display session configuration and token usage... reviewing the output for the active model, approval policy, writable roots, and remaining context capacity"; `/usage` shows "daily, weekly, or cumulative ChatGPT token activity from inside the TUI" (`/usage daily|weekly|cumulative`); `/statusline` footer items include "context stats ... token counters"; `/recap` generates a summary "without compacting its context." — [Doc: Developer commands](https://learn.chatgpt.com/docs/developer-commands.md?surface=cli)
- Custom compaction prompts are supported: `compact_prompt` (inline override for the history compaction prompt) and `experimental_compact_prompt_file` (prompt from a file). — [Doc: Config reference](https://learn.chatgpt.com/docs/config-file/config-reference.md)
- Community numbers for cost framing: "A typical Codex CLI session ... can consume 150,000–200,000 tokens within 20–30 minutes" against a 200k-window GPT-5.3-Codex default. — [Community: Codex KB, 2026-04-14](https://codex.danielvaughan.com/2026/04/14/context-compaction-deep-dive-codex-cli-claude-code-opencode)

### Inferences
- What the summary preserves is exactly "user intent + edits + thread state" at the level the template demands (progress, decisions, constraints/preferences, next steps, critical data), but implementation details go further in harness code: real user messages up to a 20k-token budget are retained verbatim (user intent, literally), tool outputs are represented by summary + world state rather than raw text.
- The `model_auto_compact_token_limit_scope = body_after_prefix` knob shows the intended steady-state: after the first compaction, only the post-prefix body is compared against the threshold, letting long-running work cycle through windows without re-tripping on the carried prefix.
- Compaction there is multi-trigger (token limit, turn-end percentage, explicit command) and gated (hooks can veto), so a Flynncode-style harness should treat pre/post-turn compaction and hook-vetoed compaction as separate policies rather than one threshold.
- Note `/compact [message]` does not work (as of a 2026-05-07 report, `SlashCommand::Compact` lacks inline-arg support and the summary isn't visible to the user), so guided compaction is done via custom `compact_prompt` files rather than an in-band instruction. — [GitHub issue #21468, 2026-05-07](https://github.com/openai/codex/issues/21468)

### Gaps
- Current default `model_post_turn_compact_threshold_percent` value (the referenced threshold percent) is not visible in the fetched config page text (it lists the key without a default); the 90% figure is from community source-tracing in issue #16068 for `total` scope.
- No primary doc found describing how compaction interacts with `codex resume` of post-compaction transcripts on disk (issue #21801 shows config `model_context_window` honored at fresh start but lost after auto-compaction — closed as "not planned" with a note that a 1M window is unsupported for GPT-5.5). — [GitHub issue #21801, 2026-05-08](https://github.com/openai/codex/issues/21801)
- Whether `/compact` now shows the summary inline to the user (requested in #21468) is unresolved in fetched docs.

## Model-side efficiency: reasoning effort, model switching for cheap subtasks, co-training with the harness

### Takeaway
Codex exposes per-model reasoning-effort control (low/medium/high/xhigh/max/ultra) plus a plan-mode-specific effort preset and answer verbosity; multi-agent machinery lets the primary agent delegate cheap work to configurable cheaper models/efforts (`agents.default_subagent_model`, `default_subagent_reasoning_effort`), and 2026 shipping includes a server-side "Multi-agent beta in Responses." OpenAI's documented co-training story is that Codex models are trained against the harness itself: trained with the 256-line output cap in place, trained to read ~200-line chunks to avoid filling context, and (Codex-Max) trained for multi-window compaction and "tasks designed to make it a better collaborator in the Codex CLI."

### Cited Findings
- `model_reasoning_effort`: "Reasoning effort advertised by the selected model, such as `low`, `medium`, `high`, `xhigh`, `max`, or `ultra`. Available levels depend on the model and client." `plan_mode_reasoning_effort`: plan-mode-specific override with a built-in preset default. `model_verbosity` (low/medium/high) is an optional Responses API verbosity override. — [Doc: Config reference](https://learn.chatgpt.com/docs/config-file/config-reference.md)
- Effort guidance from the Codex-Max release: medium reasoning effort "achieves better performance than GPT-5.1-Codex with the same reasoning effort, while using 30% fewer thinking tokens" on SWE-bench Verified; "We still recommend medium as the daily driver for most tasks"; `xhigh` is for "non-latency-sensitive tasks." — [OpenAI blog, 2025-11](https://openai.com/index/gpt-5-1-codex-max)
- Subagent cost control: `agents.default_subagent_model` ("Default model for spawned agents. An explicit spawn model takes precedence") and `agents.default_subagent_reasoning_effort`; `agents.max_concurrent_threads_per_session` ("When unset, Codex chooses the default"); `features.multi_agent` enables `spawn_agent`, `send_input`, `resume_agent`, `wait_agent`, `close_agent` (stable; on by default). — [Doc: Config reference](https://learn.chatgpt.com/docs/config-file/config-reference.md)
- Multi-agent specially-instructed: dedicated prompt templates exist (`multi_agent_instructions.rs`, plus per-tool description/parameter catalog overrides) — evidence that multi-agent turns use their own instruction block, and tool descriptions are budgeted text. — [Source: codex-rs/prompts/src listing](https://github.com/openai/codex/tree/main/codex-rs/prompts/src) (file listing accessed 2026-10-19); [Source: model_messages.rs](https://github.com/openai/codex/blob/main/codex-rs/prompts/src/model_messages.rs)
- Server-side orchestration: at DevDay 2026, "GPT-6.1 Sol ... supports Multi-agent beta in Responses and EU data residency" — [Doc: DevDay 2026, 2026-09-29](https://learn.chatgpt.com/docs/whats-new/devday-2026.md)
- Co-training claims: (a) "the model's training now includes tasks designed to make it a better collaborator in the Codex CLI" (Codex-Max blog, Nov 2025); (b) trained natively for compaction across context windows (blog + system card); (c) OpenAI staff: the gpt5-codex model is trained with the 256-line output truncation limit in place and requests bounded reads accordingly (`sed -n '1,256p' file.rs`) — [OpenAI blog](https://openai.com/index/gpt-5-1-codex-max); [System card 2025-11-18](https://cdn.openai.com/pdf/2a7d98b1-57e5-4147-8d0e-683894d782ae/5p1_codex_max_card_03.pdf); [GitHub issue #5913 staff comment, 2025-10-29](https://github.com/openai/codex/issues/5913)
- Terse-plan tooling: an `update_plan` tool with its own instruction block exists in the prompts crate (`update_plan_instructions.rs`), and the plan/patch toolchain lives in core (`apply_patch.rs`), consistent with patch-based minimal-diff editing rather than whole-file rewrites. — [Source: codex-rs/prompts/src listing](https://github.com/openai/codex/tree/main/codex-rs/prompts/src); [Source: codex-rs/core/src/apply_patch.rs path listing](https://github.com/openai/codex/blob/main/codex-rs/core/src/apply_patch.rs)
- Model-scripted efficient defaults: models have short-timeout/tier concepts — e.g., review runs can use a different model (`review_model` override, defaults to session model), and compaction selects its own effort. — [Doc: Config reference](https://learn.chatgpt.com/docs/config-file/config-reference.md); [Source: compact.rs](https://github.com/openai/codex/blob/main/codex-rs/core/src/compact.rs)
- Cheap model for cheap work at DevDay: GPT-6.1 Sol "offers near-Astra performance at a lower cost for complex coding and professional work. Use it in the API and Codex, where available." — [Doc: DevDay 2026](https://learn.chatgpt.com/docs/whats-new/devday-2026.md)

### Inferences
- The "switch models for cheap subtasks" mechanism is real but configured, not automatic: OpenAI's documented path is subagent model/effort defaults + a plan-mode effort preset, while automatic model routing (a router choosing models per call) is not present in fetched configs.
- The co-training evidence chain (trained with truncation caps → asks for bounded reads; trained with compaction → manages its own window cycling) means Codex model-side token economy is not merely prompt engineering: harness values (256 lines/10 KiB) are baked into model behavior. For a fork like Flynncode, adopting Codex-style caps only pays off if paired with behavior-adjusted prompting or fine-tuned models.

### Gaps
- `codex-mini` (2025) — no fetched 2026 source confirmed a current `codex-mini` / gpt-5.x-codex-mini cheap-tier default for subtasks; treat the "mini for cheap subtasks" idea as historical/plan instead of current fact.
- No fetched source quantifies "codex models ask follow-up questions less / spend fewer tokens" for the current GPT-6.x generation; the 30% fewer thinking tokens claim is Nov 2025 and generation-specific.

## Tool output handling: truncation caps, timeouts, transcript storage, context rebuild on resume

### Takeaway
Tool outputs are aggressively and structurally truncated before the model sees them (historically 10 KiB or 256 lines, head+tail preserved with explicit omission markers; 2026 config moves to token budgets, e.g. `tool_output_token_limit` per tool output and a "standard 20% serialization allowance" default for MCP tools). Long-running commands are handled by resumable "unified exec" background processes with `write_stdin` polling rather than large inline output. Every session is journaled to transcript files (history.jsonl / session-*.jsonl) with optional size caps, and resume reloads transcripts so context is rebuilt from the rollout rather than re-derived — compaction windows carried forward.

### Cited Findings
- 2025 hardcoded truncation: "Codex currently truncates tool outputs at hardcoded limits (10 KiB or 256 lines) before sending them to the model. Truncation preserves beginning/end while marking where middle content was removed"; markers like `[... output truncated to fit 10240 bytes ...]` and `[... omitted 34 of 324 lines ...]`. — [GitHub issue #5913, 2025-10-29](https://github.com/openai/codex/issues/5913) (subsequent OpenAI staff confirmation of the 10 KiB / 256-line values)

- Resume context rebuild: `codex resume` reloads saved transcripts ("keeping the original history intact"); `codex exec resume --last` continues non-interactive tasks; one session's context on disk is the roll-forward waypoint after compaction (see the compaction window machinery noted above). — [Doc: Developer commands](https://learn.chatgpt.com/docs/developer-commands.md?surface=cli)

### Inferences
- Codex's tool-output philosophy differs from Claude-style microcompaction: outputs are truncated at capture time to a token budget rather than later being trimmed out of context; combined with trained bounded reads, this keeps oversized output from ever entering history.
- The "20% serialization allowance" phrasing suggests a default rule-of-thumb: total tool-output serialization allowed ≈ 20% of context, with per-tool overrides for hot tools — a mechanism directly portable into Flynncode.

### Gaps
- No current default value found in fetched text for `tool_output_token_limit` (the config page listed the key but not its default; older issues indicate the 10 KiB/line values applied through at least CLI 0.5x in Oct 2025 and the mechanism has since become token-budgeted).
- Exact behavior of the truncation at the "model's default output truncation budget" (per-model in catalog) could not be confirmed beyond the config wording.
