## Identity: developer, product type, repo, maturity, how people run it

### Takeaway
Muse Code is Meta's terminal-and-CI coding agent (closed-source install; public session protocol + TypeScript/Python SDK), launched in beta on 2026-08-05 alongside the Muse Spark 1.2 coding model, now shipping at v1.4.x with macOS/Linux/Windows (voice and session messaging unavailable on Windows), a desktop app, a `muse` CLI (`curl -fsSL https://dev.meta.ai/install.sh | sh`), and a paid/consumer-contributor model. Adoption is early and reception mixed; independent harness-port authors already treat it as a supported real-world target.

### Cited Findings
- "Muse Spark 1.2 is a coding-optimized model and Muse Code is the coding agent built to run it"; Meta calls it "the first coding agent from Meta"; released as an early beta 2026-08-05 by Matthias Reso and Josh Walters on the Meta AI Developers blog — [dev.meta.ai blog](https://dev.meta.ai/resources/blog/build-with-muse-code).
- Install is one shell command putting a native `muse` binary on PATH (macOS/Linux: `curl -fsSL https://dev.meta.ai/install.sh | sh`; Windows PowerShell installer); users authenticate in a browser at dev.meta.ai (OIDC device flow) or set `META_API_KEY`, then run `muse` in a project directory; default model `muse-spark-1.2` — [Muse Code overview docs](https://dev.meta.ai/docs/muse-code) and [firstmate harness adapter](https://raw.githubusercontent.com/kunchenguid/firstmate/main/.agents/skills/harness-adapters/references/harness/muse.md) (an independent third-party port that verified Muse Code 0.1.0-R708.1, build sha 427a430436, on 2026-08-05).
- Not open-source as a harness: the binary installs from dev.meta.ai ("muse-bin-<version>" versioned binaries behind the launcher `~/.local/bin/muse`, with an auto-update channel poll; `MUSE_NO_AUTO_UPDATE=1` can pin it); Meta publishes an open cookbook ([meta-models/meta-model-cookbook](https://github.com/meta-models/meta-model-cookbook)) and a doc'd session protocol driver via `muse serve`/`muse schema` with the TypeScript SDK `npm install @muse-code/sdk` (SDK docs at [meta-models.github.io/muse-code-sdk](https://meta-models.github.io/muse-code-sdk)) — [Muse Code overview docs](https://dev.meta.ai/docs/muse-code); [firstmate adapter](https://raw.githubusercontent.com/kunchenguid/firstmate/main/.agents/skills/harness-adapters/references/harness/muse.md).
- Maturity arc: day-zero beta 0.1.0 (Aug 2026) judged by the third-party adapter as "day-zero beta" with hourly channel polls; docs changelog now reads v1.4.10 with mature-feeling fixes (desktop app↔terminal session transfer, workflows, monitors) — [firstmate adapter](https://raw.githubusercontent.com/kunchenguid/firstmate/main/.agents/skills/harness-adapters/references/harness/muse.md); [Muse Code changelog](https://dev.meta.ai/docs/muse-code/changelog) (versions listed without dates on the page).
- How people run it: interactive TUI (`muse`), headless (`muse exec "<prompt>"`, `--json` JSONL, `--max-model-steps`), programmatic (`muse serve`), in CI; a `superpowers` harness-adapters release for Muse landed 2026-10-09 ("native plugin manifest and SessionStart hook. `muse plugins install ./` then `muse plugins approve superpowers`", issue #2317), and the release notes record that "AGENTS.md used to be a symlink to CLAUDE.md, which Muse's installer rejects" — [Muse Code overview docs](https://dev.meta.ai/docs/muse-code) (headless and CI); [superpowers RELEASE-NOTES.md v7.0.0, 2026-10-09](https://github.com/obra/superpowers/blob/main/RELEASE-NOTES.md).
- Ecosystem positioning and reception: The Register covered the launch ("Meta has released a terminal coding agent called Muse Code") on 2026-08-06 — [forums.theregister.com](https://forums.theregister.com/forum/all/2026/08/06/2026); a tracking note dated 2026-09-20 calls it "Meta's first terminal-based coding agent... competitive but not state of the art at launch" (DeepSWE scores above 70 already exist), "cloud-hosted model (no local deployment)", "new entrant with limited real-world adoption" — [andyholst/ai-matrix-trends Muse Code.md](https://github.com/andyholst/ai-matrix-trends/blob/master/03%20-%20Agents/202609202055%20-%20Muse%20Code.md), citing CNBC "Meta Debuts Muse Code"; an Oct 2026 OODAloop brief describes "Early user testing reveal[ing] a mixed reception, highlighting immense potential in automated coding alongside some real-world execution hiccups and concerns over token consumption" — [OODAloop, 2026-10-13](https://oodaloop.com/briefs/technology/metas-zuckerberg-and-alexandr-wangs-high-stakes-bet-on-ai-agents).

## Context model: system prompt, instructions, memory, skills, subagent delegation

### Takeaway
Muse Code's long-term context is built from a trust-gated AGENTS.md/CLAUDE.md hierarchy, a three-scope Markdown memory system injected as an index-only summary (MEMORY.md + up to 48 file paths, contents read on demand, with background observer agents that can inject a relevant note mid-turn), skills as on-demand loadable playbooks from four sources (including ~/.claude/skills and $CODEX_HOME/skills imports), and a native subagent tree with per-child git worktrees plus four persistent background "observer" agents; everything runs on an append-only, event-sourced session log that powers resume, replay, and side-chat/fork branching that keeps side conversation content out of the main history.

### Cited Findings
- Instructions hierarchy: `muse init` writes a single AGENTS.md; "From your workspace root, Muse Code walks up to the nearest .git boundary. At each directory level, it checks `AGENTS.md`, `CLAUDE.md`, `.agents/AGENTS.md`, then `.claude/CLAUDE.md`; the first existing file in that order wins for that level"; precedence: "Project rules win over user rules" and "deeper file wins over a shallower one"; "Project rules load only after you trust the workspace. On an untrusted checkout, Muse Code ignores project AGENTS.md and CLAUDE.md until you trust it" — [Configuration and context docs](https://dev.meta.ai/docs/muse-code/configuration).
- Memory system (three scopes): personal-project memory (machine-local, outside the repo), committed project memory at `<repo>/.agents/memory/` (shared via clone), and machine-wide personal memory; layout is a `MEMORY.md` index plus one Markdown file per durable topic, e.g. deployment procedures and reasons a workaround exists — [Configuration and context docs](https://dev.meta.ai/docs/muse-code/configuration).
- Index-only injection (a deliberate token economy): "At the start of a session, Muse Code injects an *index* of your memory: `MEMORY.md` plus a list of the other Markdown files (their paths, not their contents), up to 48 files. The agent reads individual files on demand, and a background observer can insert a relevant note into a turn before the agent answers." Meta also warns memory loads even in untrusted workspaces: "Treat a repo's MEMORY.md as a prompt-injection surface" — [Configuration and context docs](https://dev.meta.ai/docs/muse-code/configuration).
- Persistent background observer agents ("async background agents" in the research blog): four are on by default — memory recall, skill recall, goal tracking, verification; "Each one watches a single axis of quality, and can insert a short advisory into the main agent's next turn without an interruption... it proposes, a reconciler decides"; and (token cost warning) "Each enabled observer makes its own model calls, so the default set of four adds token usage in addition to the main session" — [Extending and automating docs](https://dev.meta.ai/docs/muse-code/extending); blog framing: specialized background agents "remain active throughout each session, rather than being spawned for individual tasks, helping avoid redundant information gathering... Their persistence reduces latency and the need for steering" — [research.meta.ai blog](https://research.meta.ai/blog/introducing-muse-code-and-muse-spark-1-2).
- Skills: four sources (built-in; user `$XDG_CONFIG_HOME/muse/skills` + `~/.agents/skills` plus foreign roots `~/.claude/skills` and `$CODEX_HOME/skills`/`~/.codex/skills` discovered by default with a user preference to disable them; project `<repo>/.agents/skills/<skill-id>/SKILL.md` plus scans of repo `.codex/skills` and `.claude/skills`; plugin bundles). CLI: `muse skills list|inspect|enable|install|validate|import --from claude|--from codex`; bundled `/plan`, `/grill` (stress-test, records decisions and a "written scope contract in your project docs"), `/taste`, `/threejs`, and `/migrate` to import Claude Code/Codex memory notes and MCP servers — [Extending and automating docs](https://dev.meta.ai/docs/muse-code/extending).
- Skill loading is turn-scoped on demand (token economy): "a skill loads its full instructions only for the turn you invoke it on; the TUI marks it with a `Loaded skill <name> built-in` line" — [dev.meta.ai blog](https://dev.meta.ai/resources/blog/build-with-muse-code). Bundled skills are "explicit-invocation only"; a skill read earlier in a session is not reminded again in a later run of the same session ("the reminder observer and admission now honor prior-run reads") — [changelog v1.4.6](https://dev.meta.ai/docs/muse-code/changelog).
- Local file perspective: the superpowers muse-tools.md mapping treats Muse as a standard file-tool harness — table maps skill-dispatched actions to `read_file`, `write_file`, `edit_file`, `bash`, `search` (content and glob/name search), `web_fetch`, `web_search`, `subagent_spawn` ("with prompt filling" of templates like `implementer-prompt.md`), `write_todos` (or `bash` task file fallback), and `request_user_input`; it says instructions files are "CLAUDE.md or AGENTS.md in the project root. Muse loads these hierarchically where configured," skills invoke via "`muse skills`" or reading `skills/<name>/SKILL.md`, and the using-superpowers bootstrap injects at SessionStart via plugin hook — [local muse-tools.md](https://github.com/obra/superpowers) (file content in local install; local file is authoritative for the mapping). Corroboration that these are real Muse surfaces in current builds: `--disable-request-user-input` withholds `request_user_input` "so an unattended run never stops to wait on a question" — [changelog v1.4.9](https://dev.meta.ai/docs/muse-code/changelog); SessionStart hook events list includes `SubagentStart`/`SubagentStop` — [Extending docs](https://dev.meta.ai/docs/muse-code/extending).
- Subagents: "A lead session spawns child agents, hands each a bounded task"; children share the lead's checkout unless per-child worktree isolation is requested (isolated child = Muse-managed git worktree under `.muse/worktrees/`, created detached-HEAD from parent HEAD, lifecycle logged `operation_requested → prepared → lease_active → workspace_scope_activated` with `cleanup_policy: remove_if_clean`); isolation "never silently falls back to the shared checkout"; one agent tree executes 8 agents at once by default including the root (`agents.execution_capacity` 1–64; unconfigured `ultra` root uses 64); children can spawn grandchildren sharing root-tree capacity; cancellation is cooperative; everything journaled; the cookbook runs six parallel feature children with `subagent_status` roster and blocking/nonblocking `subagent_wait` — [Extending docs](https://dev.meta.ai/docs/muse-code/extending); [dev.meta.ai blog](https://dev.meta.ai/resources/blog/build-with-muse-code) (fan-out recipe).
- The local muse-tools mapping and the official docs agree on delegation shape (spawn isolated children, one task each) and the muse-tools note — "If no subagent tool is available, do the work inline rather than inventing tool calls" — plus superpowers's separate Claude-Code-only note that an orchestrator can be nested a layer down on a cheaper mid-tier model (not offered in muse-tools.md) — [local claude-code-tools.md](https://github.com/obra/superpowers) for contrast.
- Session/event-sourcing context model: every run is an append-only event log (model calls, tool calls and results, approval decisions) at `~/.local/share/muse/sessions/YYYY/MM/DD/<session-uuid>/session.jsonl` (firstmate: native sub-agent logs live under `subagent/<child-session-id>/session.jsonl`); `muse resume` replays from the last recorded step ("an interrupted or crashed run replays cleanly... It rebuilds the conversation, closes the interrupted turn, and continues"; partially-landed side effects are marked outcome-unknown and the agent is told to verify before retrying); `--no-session-log` forfeits resume, trajectory export, and peer messaging — [Working with the agent docs](https://dev.meta.ai/docs/muse-code/interactive); [firstmate adapter](https://raw.githubusercontent.com/kunchenguid/firstmate/main/.agents/skills/harness-adapters/references/harness/muse.md).
- Branching/parallelism without context bleed: `/fork` branches a new session from the current point; `/rewind` restores an earlier message as an unsent draft in a NEW retained session leaving files unchanged; side conversations (`/side`, `/btw`) run their own thread seeded from a snapshot of the main transcript "and never enters the main history"; parallel live sessions in separate terminals use `muse -w` per-writer managed worktrees — [Working with the agent docs](https://dev.meta.ai/docs/muse-code/interactive); [Session messaging docs](https://dev.meta.ai/docs/muse-code/session-messaging).
- Goals: `/goal <objective>` keeps the agent on a long-horizon objective ("runtime queues a follow-up to continue unfinished work... prompts the agent to `report_progress` if the agent goes about 10 model steps without one"; requirement-by-requirement completion check before declaring the goal done; Esc auto-pauses an unfinished goal); `/loop` schedules recurring prompts as cron jobs (default every 10 minutes, auto-expire after 7 days; the agent manages loops with its cron tools) — [Working with the agent docs](https://dev.meta.ai/docs/muse-code/interactive).
- Workflows (rollout-gated): structured multi-agent orchestration with parallel groups, stages, a control room showing "phases, child-agent progress, elapsed time, token usage, errors, and final results"; agent definitions can pick each child's model and reasoning effort — [Muse Code overview docs](https://dev.meta.ai/docs/muse-code); [Working with the agent docs](https://dev.meta.ai/docs/muse-code/interactive); [changelog v1.4.8/v1.4.7](https://dev.meta.ai/docs/muse-code/changelog).
- A documented privacy-relevant context behavior from the independent adapter (day-zero build): "Muse sends operator rules from `~/.claude` to Meta-hosted inference on every run" (its own gainful notice shows once), project AGENTS.md retained; the experimental kill switch is `MUSE_EXPERIMENTAL_FOREIGN_PERSONAL_CONTEXT_KILL=on` (`--no-foreign-personal-context` was exec-only) — [firstmate adapter](https://raw.githubusercontent.com/kunchenguid/firstmate/main/.agents/skills/harness-adapters/references/harness/muse.md).

### Inferences
- The context model pushes durable knowledge out of conversation: rules into version-controlled AGENTS.md, decisions into docs via `/grill`, memory into MEMORY.md files whose contents are only fetched when relevant, and audit/progress state into the event log — so the model-visible transcript stays small by design ("context that finds you" per the launch post).
- The four-source skill system (including foreign Claude Code/Codex roots) plus `/migrate` is a deliberate front-door migration play from incumbent agents, and doubles as a context-economy feature because prompts only pay for skills actually loaded on the turn they are used.

### Gaps
- The literal system prompt (base instructions) is not published anywhere I found; the closest public facts are the instructions-file hierarchy, the once-per-run foreign-rules notice, and the memory index injection. I found no source enumerating Muse Code's full default tool schema beyond the tools observed in docs/recipes (subagent_spawn/status/wait, write_todos, request_user_input, cron, bash, search, read/edit/write_file, web_fetch/search).
- Whether `write_todos` is still the native todo tool name in 1.4.x could not be verified from primary docs (the docs call it the "Tasks" surface); it is established only by the local muse-tools.md mapping, whose stated ground is the 0.1.x/0.2.x era and the superpowers v7.0.0 adaptation work (2026-10).

## Token techniques: compaction, deferred loading, truncation, caching, routing, batching/async

### Takeaway
Muse's token economy layers (1) auto/manual lossy compaction with checkpoints that sessions resume from instead of rereading history, (2) batched tool-call commit with a PostToolBatch hook and results that reach the model without transcript rescans, (3) lean tool-surface options (`--preset empty`, MCP toolset globs) and an 8-level reasoning-effort ladder including `ultra` that also makes the agent delegate more, (4) turn-scoped skill loading and index-only memory injection, (5) three-way Steering/Queue/Notify-only message delivery where "Notify only" never touches the recipient's model context, (6) prompt-cached input pricing ($0.15/1M) plus a subscriber "contributor" mode routed to a `-contributor` model family limited by tokens (5-hour rolling window) instead of request count, and (7) async background agents and subagents whose results drain to a parent only when it next needs them, avoiding redundant gathering; the model itself was co-trained with the harness on "recipe optimizations for goals, compaction, and subagents."

### Cited Findings
- Compaction: `/compact` "replaces earlier model-visible history with an LLM-generated summary to reclaim context room. It's lossy for the model's context (summarized, not verbatim), but does not clear your on-screen scrollback. Muse Code also compacts automatically when context fills. A manual /compact never counts against the auto-compaction budget. Compaction fires the PreCompact and PostCompact hooks" — [Working with the agent docs](https://dev.meta.ai/docs/muse-code/interactive). Compaction checkpoints ride along with each compaction ("A context compaction now always saves its resume checkpoint together with it; if the checkpoint cannot be written, the compaction is skipped and retried at the next step") — [changelog v1.4.7](https://dev.meta.ai/docs/muse-code/changelog); long sessions "now resume quickly from their latest compaction instead of rereading most of the session log" — [changelog v1.4.6](https://dev.meta.ai/docs/muse-code/changelog); `muse exec` "waits for context compaction to finish before exiting, so resumed sessions keep their compacted summary" — [changelog v1.4.8](https://dev.meta.ai/docs/muse-code/changelog); compaction keeps the request detail needed to "rebuild the exact prefix" rather than fall back to a bounded summary — [changelog v1.4.8](https://dev.meta.ai/docs/muse-code/changelog).
- Compaction in the model (not just the harness): Muse Spark 1.2 "leverages planning to sequence work, goal conditioning to maintain direction, and context compaction to retain the knowledge needed to sustain progress" across 1,000+ tool calls and up to 24-hour runs; co-training included "rejection sampled harness trajectories and recipe optimizations for goals, compaction, and subagents" — [research.meta.ai blog](https://research.meta.ai/blog/introducing-muse-code-and-muse-spark-1-2). The dev blog markets "planning, goal conditioning and context compaction to hold direction over hours, plus asynchronous and parallel tool calls, so work continues while results are still pending," over "a 1M-token window [that] holds dependency graphs, legacy code and thousands of files in one session" — [dev.meta.ai blog](https://dev.meta.ai/resources/blog/build-with-muse-code).
- Batched tool calls / batch-level hooks: "PostToolBatch runs once after each committed batch of tool calls and receives them in order; it can block the batch with a reason, stop the turn, or add context" — [Extending docs](https://dev.meta.ai/docs/muse-code/extending) (first shipped in changelog v1.4.6). Performance fix: "Large batches of parallel tool calls now land their results without rescanning the transcript for each one" — [changelog v1.4.8](https://dev.meta.ai/docs/muse-code/changelog). Context-dedup of commands: "Bash command results no longer repeat the command back to the model, so a long inline script takes up context once instead of twice" — [changelog v1.4.8](https://dev.meta.ai/docs/muse-code/changelog).
- Deferred/lean tool loading: `--preset empty` "starts a session with no built-in tools; the model gets only the tools of MCP servers you configured" — [changelog v1.4.8](https://dev.meta.ai/docs/muse-code/changelog); a named toolset `run.toolset` selects MCP tools by name or glob (`mcp__docs__*`, `mcp__docs__search*`) so only intended tools are exposed, and missing selected tools stop the run before the model is contacted — [Extending docs](https://dev.meta.ai/docs/muse-code/extending) (glob selection added v1.4.6). MSP tool economy at the API layer: Meta Model API has a "Tool search" capability that keeps clients from having to ship full tool lists to the model (categorized API capability; the docs I fetched confirm the section exists) — [Model API docs nav](https://dev.meta.ai/docs/tool-search).
- Early result caching/truncation of stale tool output: "A session whose model reused a tool call id for two same-length results no longer becomes impossible to resume or compact after old tool results are cleared" and reminders "expire" — indicating the harness clears old tool results and expires reminders from context, with corrected `/compact` token counts — [changelog v1.4.10](https://dev.meta.ai/docs/muse-code/changelog); "Allow one more attempt to clear old tool results after reopening a session whose required compaction failed" — [changelog v1.4.9](https://dev.meta.ai/docs/muse-code/changelog).
- Reasoning-effort ladder (thinking tokens are billed as output): `--reasoning-effort` accepts `none`, `minimal`, `low`, `medium`, `high` (default), `xhigh`, `max`, `ultra`; "xhigh is an optional premium-precision level, and max is the deepest reasoning level — extended reasoning beyond xhigh... ultra is a client-side setting that maps to each provider's highest supported reasoning level and can make Muse Code delegate more aggressively; where a provider doesn't support it, a request for ultra runs at xhigh. The Meta provider does not accept none" — [Configuration docs](https://dev.meta.ai/docs/muse-code/configuration); day-zero adapter observed default `high` with none/minimal "unreachable" on that early build (evolved since) — [firstmate adapter](https://raw.githubusercontent.com/kunchenguid/firstmate/main/.agents/skills/harness-adapters/references/harness/muse.md); `subagents now honor the reasoning effort set in their agent definition` — [changelog v1.4.10](https://dev.meta.ai/docs/muse-code/changelog).
- Message delivery economy across sessions ("deliver without waiting"): peer session messages ≤8,192 bytes delivered three ways — "Steer the active turn: add the message to the recipient's current work at its next safe model step. Queue for the next turn... Notify only: show and record the message without adding it to the recipient model's context"; "Muse Code defaults to waking the recipient when it is idle"; peer messages are untrusted data that cannot grant approvals/permissions — [Session messaging docs](https://dev.meta.ai/docs/muse-code/session-messaging). Intra-turn economy mirrors it: Enter injects text mid-turn; Alt+Enter queues it for the next turn; subagent results "drain back to the parent automatically once the parent's turn is idle, or you can block on one with subagent_wait" — [Working with the agent docs](https://dev.meta.ai/docs/muse-code/interactive); [dev.meta.ai blog](https://dev.meta.ai/resources/blog/build-with-muse-code).
- Observer-agent self-check economy (vs. always-on review): the built-in Auto-review reviewer hands approvals to the human "once the reviewer has used 15 steps without reaching a decision, instead of letting a single review run for dozens of steps and use many tokens" — [changelog v1.4.8](https://dev.meta.ai/docs/muse-code/changelog).
- Model routing and caching pricing: pay-as-you-go `muse-spark-1.2` at "$0.15 / 1M cached input, $1.25 / 1M input, $4.25 / 1M output" (Muse Spark is a reasoning model; "those tokens [thinking] are billed as output"); the subscriber "contributor tier" (`/model to muse-spark-1.2-contributor`) is "rate-limited by tokens in a rolling 5-hour window, rather than by request count" and may be used to improve Meta products; contributor mode "routes each model family to its served contributor model" — [dev.meta.ai blog](https://dev.meta.ai/resources/blog/build-with-muse-code); [changelog v1.4.8/v1.4.6](https://dev.meta.ai/docs/muse-code/changelog). OpenRouter availability extends routing beyond Meta's gateway — [dev.meta.ai blog](https://dev.meta.ai/resources/blog/build-with-muse-code). A third-party guide claims contributor pricing of "or $0.10/$0.20 if you let Meta train on your code" — secondhand, not visible in the primary page I fetched — [codersera guide](https://codersera.com/blog/muse-code-complete-guide-2026).
- The muse-tools.md token-economy angle was narrower than the premise: the local file's only explicit economy levers are `read_file` reuse vs. `search`, `write_todos` as first-class checklist tracking (with `bash` task-file fallback), `subagent_spawn` with pre-filled prompt templates, and session-start injection of only the bootstrap; the phrases "batch tool calls" and "deliver messages without waiting" do NOT appear in this version — [local muse-tools.md](https://github.com/obra/superpowers); those mechanisms are instead documented first-party (PostToolBatch hook; steer/queue/notify delivery) as cited above.

### Inferences
- Muse pushes compact leaves upward through async delivery (notify-only, idle wake, drain-on-idle) rather than through prompt surgery, which — combined with observers that only interject "a short advisory... without an interruption" — suggests the harness's long-context march is designed around minimal interruption tokens rather than heavy summarization alone.
- The contributor mode doubles as both a cost lever for users (token-window unlimited-feeling usage) and a data lever for Meta (usage may be used to improve products), a tradeoff mainstream vaulted agents do not offer in the same shape.

### Gaps
- I could not find a primary statement of prompt-caching behavior inside the Muse Code CLI itself (the $0.15/1M cached-input price comes from the muse-spark-1.2 Model API pricing table the CLI draws from; whether every CLI turn hits cache is undocumented).
- No published numbers on compaction ratio/thresholds (when auto-compaction fires exactly) were found.
- "Tool search" is documented as a Model API capability; I did not confirm it is used inside the Muse Code CLI's own request path (I did not retrieve the tool-search page; only the nav).

## What makes Muse notably cheaper or leaner — and what makes it more expensive

### Takeaway
Muse is lean by classification (index-only memory, turn-scoped skills, cleared stale tool results, notify-only messaging, batched results, compaction checkpoints) and by pricing (cheap cached-input rate and a volunteer-priced contributor tier), but its default observer-agent quartet and always-on auto-review add real token cost, and one independent assessment pegs token consumption as an adoption concern.

### Cited Findings
- Default-on overhead: "All four observers, including verification, are on by default... Each enabled observer makes its own model calls, so the default set of four adds token usage in addition to the main session" — [Extending docs](https://dev.meta.ai/docs/muse-code/extending).
- Auto-review economy fix: "Auto-review now hands an action to you for approval once the reviewer has used 15 steps without reaching a decision, instead of letting a single review run for dozens of steps and use many tokens" — [changelog v1.4.8](https://dev.meta.ai/docs/muse-code/changelog).
- Idle daemon economy: "While idle, `muse serve` no longer rewrites the lock file of every old empty session... every few seconds" — [changelog v1.4.9](https://dev.meta.ai/docs/muse-code/changelog).
- Unattended turn economy: `--disable-request-user-input` keeps a run from stopping for a question; `--yolo` implies it; `--max-model-steps` caps a headless run's model steps so a stuck task cannot loop indefinitely — [changelog v1.4.9](https://dev.meta.ai/docs/muse-code/changelog); [Extending docs](https://dev.meta.ai/docs/muse-code/extending).
- Independent reception flag: "some real-world execution hiccups and concerns over token consumption" in early user testing — [OODAloop, 2026-10-13](https://oodaloop.com/briefs/technology/metas-zuckerberg-and-alexandr-wangs-high-stakes-bet-on-ai-agents).
- The distinct consumer "Muse" (same brand family, NOT the coding agent) shows what Meta optimizes for cost elsewhere: contributor-like rates and agent app popularity; this is context for deduplicating claims in downstream reports — [Yahoo Finance, 2026-09-22](https://finance.yahoo.com/markets/stocks/articles/buy-hold-sell-meta-stock-125100835.html).

### Inferences
- Net-net, Muse's lean-ness is promotional at launch (free contributor usage) and architectural in the middle (progressive disclosure everywhere: memory index, turn-scoped skills, toolsets, batch hooks), but the observer-task default makes base-agent overhead nontrivial, which aligns with the reported token-consumption concern.

### Gaps
- No benchmark comparing Muse Code tokens-per-task against Claude Code/Codex CLI exists in what I found; "cheaper or leaner than mainstream agents" remains unverified quantitatively — only mechanism-by-mechanism.
- Contributor-tier exact prices were not published on the pages I fetched (see conflict noted in Token techniques).
